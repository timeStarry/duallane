## 完整子会话链路（2026-09-11 后续修正）

此前抽取只统一了聊天外壳，话题仍单独简化内容和发送协议，因此图片、表情与消息操作缺失。
本次把话题作为真正的群聊子会话，前后端均复用普通消息实现：

- 同一完整消息模型、结构化渲染器、表情库、内容编码、回复自动提及、长消息转 TXT 和对象命令。
- 同一上传服务；话题文件使用 private_staging，发送关联后由有效空间、群、话题成员读取。
  上传者、管理员不能绕过未加入或退出话题后的限制，也不将正文写进普通群消息流。
- 提交时捕获原目标、附件、内容、回复、同步与客户端 ID，立即释放当前编辑区。
  附件后台上传不阻止下一条文本；失败在原消息重试，已完成附件不重复上传。
  取消批次停止尚未开始的文件；导航晚响应不清新草稿，父群撤权清理对应话题状态。
- 话题中栏随可访问父群集合变化重新读取；恢复群权限后自动出现可访问话题，
  撤权后立即排除旧行，不能等待某一次话题消息事件才更新。
- 创建群聊／私聊成功后使先前的会话列表请求失效，再读取新权威列表。
  避免迟到旧快照移除新会话并切回旧页面；登录或访问上下文已失效时不应用创建结果。
- Go 话题事务适配器调用普通消息创建服务，统一校验、关联、幂等、审计、事件与投影。
  原路径兼容增加完整消息字段及 around 历史定位，不增加迁移或第二个写入者。
- 话题反应、个人隐藏/恢复、撤回、常驻、历史与引用定位使用原对象接口。
  公共修改受话题 open 状态限制；关闭后仍可阅读、预览和管理自己的隐藏状态。
  撤回在同一事务清除同步卡摘要，常驻保留原每人每群额度及成员访问限制。

话题顶部的低频按钮收至默认关闭的“话题详情”：桌面右侧面板，手机独立详情层，
关闭与 Escape 返回触发项；所属群与参与人数留在紧凑横幅中，发送时同步选择留在输入区。
文件/成员视图保留置灰的中栏按钮槽位；输入区外围透明，只有输入器本体保留主题表面和悬浮轮廓。
外观明暗模式恢复为系统、浅色、深色三项图文单选；按用户参考图保留整体圆角底座、
内嵌选中块、细轮廓与轻微阴影，不复用导航 Tab 的底边指示条。

## 同一套会话界面（此前外壳抽取阶段）


话题是群聊下的子会话。它沿用群聊的消息行、作者与时间、连续消息分组、日期分隔、
回复预览、输入框、格式工具、提及、展开编辑区、发送失败与重试交互。
所属群、话题状态、加入/退出、通知及管理操作放在会话标题下的简洁横幅中。
同步到群聊等话题动作由该领域提供，不能复制出另一套消息行或输入组件。

正式实现以 `features/conversation/WorkspaceChatPanel` 为共享视图。
群聊与话题各自提供消息数据、真实能力和回调；结构化正文、表情、卡片等通过有类型的
渲染接口接入。依赖方向是领域适配到共享视图，共享视图不反向导入 `App` 或自行写入后端。
旧话题专用消息行、输入框和提及菜单的重复实现及样式随接入移除。

共享界面不会将话题消息改为普通群消息。话题的加入条件、独立草稿、回复目标、未读、
通知级别、同步引用、关闭/归档、幂等与迟到响应保护继续由现有控制器和 API 负责。
只展示该领域实际支持的操作；不能用无效回调伪装文件、图片表情、常驻或撤回能力。
本轮没有数据库迁移或新的服务端消息写入路径，也不改变 P2P 与 Workspace 的保存边界。

集成审查同时补齐三个交互边界：本地待发送／失败消息不向服务器提交隐藏操作；
图片表情发送完成后只在原会话、原编辑器且用户没有移开焦点时恢复焦点；
话题从历史位置返回最新消息时补记已读。已读请求只确认当前可见、已加入、位于底部的
服务器消息，去重并串行处理，迟到响应不能改写其他话题的游标。

## 连续短消息精修

同日、相邻五分钟内、同一作者身份的连续消息共用一个视觉表面：组首只有上圆角，
组中平直衔接，组尾只有下圆角；普通相邻组间隔 12px。本人／他人的底色保持区别。
桌面悬停只强调当前消息，操作区继续占据行内空间，手机命中区不因紧凑排列而缩小。

分组由共享视图的 `message-grouping.ts` 推导，按作者 ID、类型与本人属性判断，
不能因同名误合并。日期、未读分隔、隐藏消息段、撤回、系统消息和显式回复均切断分组。
话题回复即使原消息不在当前历史窗口，也通过 `replyToMessageId` 保留独立边界，
不虚构原文预览。直聊、群聊和话题统一生效，P2P 消息表面本轮没有改动。

每条消息仍使用原 ID／React key 和独立 DOM 节点；没有引入外层分组容器。
新增消息、隐藏／恢复和未读分隔移动只更新边缘与作者信息，不替换正在操作的消息节点。

真实双用户验收还复现并修正了两项阅读位置问题：

- 初始窗口只有 20 条时，实时追加曾直接裁掉最早一条。用户停在历史位置时，前端保留

  沿用高度差回退。原有会话、列表、访问和请求时效检查继续生效。
