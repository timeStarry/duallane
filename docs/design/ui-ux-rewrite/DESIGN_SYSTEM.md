状态：最终已采纳的视觉与组件规则，覆盖本次重构及后续评审反馈。
实现、验收和发布状态分别记录在 [架构](ARCHITECTURE.md)、[验收矩阵](ACCEPTANCE.md)
和 [PR 验证记录](PR_VERIFICATION.md)；规则已确定不代表所有设备均已验收或已经发布。

本文是视觉角色、控件选择、几何、主题展示、消息表面和材质动效的唯一规范定义。
导航与任务流程引用 [体验规格](EXPERIENCE.md)，对象操作和个人设置流程引用
[对象操作与个人设置](CONTEXT_AND_SETTINGS.md)，领域权限与数据约束继续遵循产品契约。

不得作为正式值源、兼容皮肤或照抄页面的依据。

## 1. 视觉原则

以细腻平面、柔和层次、少量透明材质和克制动效表达质感。正文始终是最主要的内容。

- 使用排版、留白、对齐和细分隔建立层级。聊天列表和正文不逐条套卡片。
- 人物使用圆形头像；空间、群和工具实体使用圆角方形。Bot 另有清楚的身份标记，不能仅靠头像形状判断。
- 私密直连和共享空间有稳定的名称、图标、说明与语义色。主题变化不改变两条通道的含义。
- 常规设置使用有标题的分组与行；安全命令、一次性凭证和复杂配置有明确边界，避免长页面卡片堆叠。
- 图标沿用 Lucide；动效说明状态变化，颜色和模糊不能独自传达必要信息。

## 2. 排版与尺度

| 用途 | 采用的尺度与约束 |
| --- | --- |
| 消息正文 | 默认 15px，适合中英文混排的行高约 1.6；用户字体设置需单独验证 |
| 页面／会话标题 | 通常 18–24px；产品内容页不使用报告封面的展示字号 |
| 控件与设置正文 | 14–15px |
| 辅助文字 | 通常 12–13px；不靠降低透明度掩盖对比度不足 |
| 时间戳 | 紧凑场景可为 11px，不承载唯一操作提示 |
| 基础间距 | 4 / 8 / 12 / 16 / 24 / 32px |
| 圆角 | 标签 6px，控件 10px，输入编辑区域 16px，对话框 20px，实体头像参考 11px |
| 操作命中区 | 重复和主要触控操作至少 44 × 44 CSS px；小图标也有足够命中区 |

字体优先使用项目的系统字体栈和可用中文字体，不为造型额外引入远程字体依赖。
密度改变列表行高、留白和间距，不能暗中缩小正文字体或手机命中区。
200% 缩放、长名称、连续字符、换行和动态内容需通过验收。

## 3. 布局与窗口尺度

按内容容器的实际可用宽度适配，同一套组件承接桌面、窄窗和手机。
主导航、可折叠中栏、单列表页面与详情层的归属按 [体验规格](EXPERIENCE.md) 执行。
其视觉约束是：固定工具保持固定位置，禁用状态保留原槽位；标题、状态和操作按内容收紧，
不能把状态标签拉满横栏。辅助面板须有清晰的头部、内容和操作分组，不能只为旧布局套新圆角。

弹层和窗格内部滚动不制造页面横向溢出；长名称、200% 缩放、安全区和软键盘纳入实际测量。
控件能否并排由剩余宽度决定，不能把桌面参考最小宽度强加到手机。
打开详情、改变主题和切换窗口尺寸不重建编辑器、选中对象或阅读锚点。

| 当前 Web 布局基准 | 明确约束 |
| --- | --- |
| 宽屏 Workspace（>1100px） | 主导航轨 72px，中栏 288px，详情栏 360px，正文使用剩余空间；中栏与详情关闭时实际释放占用 |
| 窄桌面／分屏（761–1100px） | 主导航轨 72px、中栏 260px；详情覆盖正文，宽度上限 360px 且不覆盖导航轨；不强行塞入四列或改变发送目标 |
| 手机与窄窗 | 760px 及以下按单层任务页组织；320px 是必须检查的窄宽，主内容不横向溢出 |
| 个人设置 | 桌面分类栏 216px，正文容器按可用空间收敛；手机按目录／类别／子页逐层显示，不把桌面两栏压缩成两列 |
| 文件卡片 | 网格基准最小列宽 220px，可用宽度更窄时使用其实际宽度；文字内距 12px，不能以图像宽度撑开文字区 |

这些是统一布局基准；具体断点与容器实现归壳层及所属页面 CSS。新增布局调整必须更新本表，
并复验断点两侧、长内容和真实窗口剩余空间，不能另造页面专属的尺寸规范。

## 4. 材质与层次

| 层 | 用法 | 限制 |
| --- | --- | --- |
| 页面与消息内容 | 中性底色、清晰文字，平面优先 | 不在每条消息或列表行上叠加重阴影 |
| 输入区域／局部工具 | 微弱轮廓、低层阴影或色面分离 | 聚焦反馈保持稳定尺寸 |
| 侧栏／菜单／浮层 | 层级适当增加，边界可辨 | 不能通过多重卡片与过大的模糊半径制造层级 |
| 固定导航／工具栏 | 有内容经过其下方时可使用局部透明与背景模糊 | 有不透明回退，文字和图标对比达标 |
| 模态对话框 | 独立遮罩、明确焦点与关闭／取消路径 | 不把正常浏览流程堆成多层模态 |

阴影、透明度和模糊强度属于共用材质 Token；主题仅允许提供受约束的取值。
Web `backdrop-filter` 是材质近似，不能称为已实现平台原生 Liquid Glass。
关闭透明效果或不支持模糊时使用语义实色，保留层级和操作可辨性。

## 5. 主题架构

### 5.1 分层与唯一数据源

```text
ThemeDefinition（主题家族的完整明暗语义值）
  → Semantic tokens（用途和状态）
  → Component tokens（组件尺寸与材料）
  → 同一套组件与页面
```

正式色值的唯一源是 [tokens.ts](../../../apps/web/src/ui/theme/tokens.ts)，
[appearance.ts](../../../apps/web/src/ui/theme/appearance.ts) 负责语义 CSS 变量、材质、动效、圆角和密度映射。
组件专有几何集中在所属正式组件 CSS 中，不能从原型 JSON 生成另一套运行时值。
原型副本无需与产品构成双向同步契约；产品修改直接更新正式值源及其验证。
新增页面与未来平台映射复用语义角色，不导入原型脚本或复制报告页面 CSS。

### 5.2 语义角色

| 类别 | 正式语义键 |
| --- | --- |
| 表面 | `bg`, `surface`, `soft`, `elevated` |
| 文字 | `text`, `muted` |
| 边界／交互 | `line`, `control`, `focus` |
| 私密直连 | `direct`, `direct-soft`, `on-direct` |
| 共享空间 | `shared`, `shared-soft`, `on-shared` |
| 操作结果 | `success`, `success-soft`, `warning`, `warning-soft`, `danger`, `danger-soft` |
| 头像辅助 | `avatar-a`, `avatar-b`；不得取代人物／Bot 身份说明 |

组件不得硬编码“橙色就是私密”或“青蓝就是主要按钮”。使用语义变量并同时指定色面上的前景色。
色板中的细分隔线不承担必要的控件轮廓；输入框、焦点和状态采用符合对比要求的相应语义值。

### 5.3 家族与偏好

| 稳定 ID | 名称 | 色彩方向 |
| --- | --- | --- |
| `original` | 原色（默认） | 铜橙／青蓝 |
| `grove` | 苔原 | 莓红／松绿 |
| `dusk` | 暮色 | 赭金／靛紫 |
| `beige` | 米色 | 暖灰米白底面，棕褐／蓝灰 |
| `minimal` | 极简 | 黑白灰阶底面与通道强调；保留语义状态色 |

每个家族必须包含完整 `light` 和 `dark`。系统模式是解析用户偏好的方式，不是第三套配色。
主题卡片只保留微型产品预览、标题与选中标记，不显示小字描述。卡片沿单行横向浏览，
提供触摸滚动、鼠标拖动、左右浏览按钮和键盘入口。拖动／浏览不能误触主题保存，
当前选择与焦点清晰可辨，重新进入时选中项可见。只允许条带内部横向滚动，页面不溢出。

极简主题参考 [GitHub Primer 的中性色与语义色分工](https://primer.style/product/getting-started/foundations/color-usage/)
及 [组件颜色角色](https://www.primer.style/product/primitives/color/)，结合用户指定的 ChatGPT／GitHub 简洁方向进行适配。
具体色值由本项目按文字、背景和控件对比度确定，不宣称复刻其整套配色。
正式偏好类型、版本、默认值和迁移由 [preferences.ts](../../../apps/web/src/ui/theme/preferences.ts)
定义；按设备保存主题、模式、密度、动效和透明度，不默认跨设备同步。
五项偏好互相独立，主题切换不能覆盖其它选择。系统模式解析为当前浅色或深色，不另存第三套色板。
系统减少动态效果的要求优先；减少透明度、强制颜色或平台缺少模糊能力时解析为不透明材质。

### 5.4 扩展与失败处理

- 未知主题 ID 回退内置 `original`，保留合法的独立模式等偏好；不支持的偏好记录版本整体回退正式默认值。
- 必需语义键缺失、颜色格式无效或对比度不合格的主题不得发布；材质与尺度使用正式统一映射。
- 当前主题来自内置注册表，未开放任意外部主题导入。无效偏好使用完整内置回退，不能把半套主题与旧 CSS 混用。
- 新主题通过同一对比度、状态、布局、表单和内容测试，不允许单独复制 `Button`、`Composer` 或页面。
- 主题配置是受校验的数据，不执行脚本，不注入任意 CSS／URL，也不携带会话或身份数据。
- 本地存储失败时保留当前内存外观，显示失败与重试入口，不丢草稿、不卸载编辑器。
- 原生端未来映射这些语义、状态与偏好；平台控件、手势、窗口和字体单独适配，不能将 CSS 等同跨端实现。

## 6. 共用组件与行为

| 组件族 | 必须统一的内容 |
| --- | --- |
| Button / IconButton / Link | 主次与危险级别、加载、禁用原因、命中区、焦点、键盘 |
| Input / Textarea / Select / Switch | 标签、说明、校验、只读／禁用、保存失败与重试 |
| Menu / Tabs / Popover / Dialog / Sheet | 导航与选择语义、焦点、返回／关闭、遮罩层级 |
| Avatar / Identity / Badge | 人物／实体／Bot 身份、回退、未读与连接状态区分 |
| Message / Composer / Attachment | 排版、回复、提及、富内容、草稿、发送生命周期与媒体动作 |
| SettingsRow / Feedback / EmptyState | 清晰分组、异步状态、可恢复错误、受限与终止状态 |

不同通道和会话类型通过能力声明决定可用操作，共用组件不等于共用存储或强行开放相同功能。
对象菜单、移动动作面板与个人设置的布局／层级／保存细则统一引用
[对象操作与个人设置](CONTEXT_AND_SETTINGS.md)，不在各页面自定义右键或长按行为。
群聊和话题使用同一完整消息、富内容、附件和编辑器组件；话题只改变消息作用域及真实领域操作。
话题详情按需展开，不把参与、通知与管理工具常驻挤占正文。完整共用与权限契约见
[体验规格](EXPERIENCE.md)和[话题领域契约](../../WORKSPACE_GROUP_TOPIC_DESIGN.md)。私密直连的发送与保存由其独立适配层处理。
复杂 Bot 卡片和 Echo 工作流保留结构化协议、授权和失效状态，在统一容器中呈现。

### 下拉选择、滚动条与数值滑块

这三类统一使用正式组件和平台适配，浏览器提供默认外观不是遗漏设计的理由。
先按下一节的语义选择控件，再应用其视觉状态；不是所有互斥选项都使用下拉。

| 组件 | 正式视觉与交互要求 |
| --- | --- |
| Select / Combobox | 触发器使用 10px 圆角、统一字体与箭头；选项面板 14px 圆角、细轮廓与菜单层次，选项行至少 44px。展开宽度承接触发器，靠近边缘时调整方向，长列表内部滚动 |
| 下拉状态 | 当前值、占位、展开、选中、悬停、键盘焦点、禁用、无结果、加载和失败都有定义；选中使用勾选标记和浅色底，不混用 Tab 的导航指示条 |
| 下拉操作 | 键盘打开、方向键定位、Enter 提交、Escape 取消、焦点恢复；可搜索项支持输入法与过滤。选项选择与普通动作菜单保持不同语义 |
| 手机选择 | 短列表可使用可达的浮层；长列表／可搜索内容使用共用 Sheet 或完整选择页。返回、取消、系统键盘及安全区必须真实验收，不叠加多个选择层 |
| 滚动条 | 桌面使用中性、轻量轨道与滑块，随主题切换；保留系统滚动、惯性、拖动、触控板与键盘。不隐藏唯一滚动提示，不重写全局滚轮或用 JS 模拟滚动换外观 |
| 平台滚动适配 | 支持的浏览器使用 `scrollbar-color`／`scrollbar-width`，触屏和强制颜色模式优先平台可用性；允许系统决定叠加条的显示与实际粗细。为需要稳定对齐的内部窗格预留槽位，换主题不重置位置 |
| Range / Slider | 4px 轨道、16px 圆点，整体至少 44px 操作高度；颜色表示已调整范围。提供当前值与精确输入，方向键步进、Home／End 到端点；越界或无效输入就地提示，不静默写入 |

正式实现由 [ui/primitives](../../../apps/web/src/ui/primitives/README.md) 提供共用选择器、
滑块与滚动区域样式。Select 使用正式渲染的列表框及移动选择页，不能依赖原型的
`appearance: base-select` 渐进增强来宣称跨浏览器一致性。平台覆盖情况以验收证据为准。

### 导航选中态与分段单选

导航选中态采用中性圆角底面与笔直等宽细条。目录、设置分类、会话选中项和横向同级视图
共用这套结构；不使用沿圆角转弯的内阴影、整边粗 border 或重投影表示选中。
它表达所在位置；改变一个固定偏好或筛选值使用分段单选，二者不可混用。

| 导航结构 | 规则 |
| --- | --- |
| 指示条 | 厚度 2px；常规导航／Tab 两端各内缩 10px，端部圆角 1px；手机根页面底部导航采用两端 8px 内缩、直端这一明确的紧凑适配。条不能随底面圆角变形或渐细 |
| 底面 | 10px 圆角，`surface` 中性表面、1px `line` 细轮廓；保持文字与图标清晰 |
| 条与框的关系 | 固定间隔 5px；为指示条和间隔预留共 7px 槽位，底面和内容都不覆盖它 |
| 侧边型 | 条在左侧，适合纵向目录、分类、会话列表；支持 RTL 的正式实现改用逻辑起始边 |
| 底部型 | 同一结构旋转到下边，适合横向 Tab 和空间导航 |
| 选中与悬停 | 选中出现底面和指示条；悬停仅改变底面，不出现选中条 |
| 焦点 | 键盘焦点保留独立外框；指示条不代替焦点，也不只靠文字颜色表达选中 |

槽位在未选中时也保留，选中、悬停和聚焦都不改变命中区、文字位置或相邻项尺寸。
重复触控目标仍至少 44×44px；紧凑密度不能缩小点击范围。转换只使用短淡入／淡出，
不加滑动弹簧、发光或厚阴影；减少动态时直接显示最终状态。
正式结构由 [Selection.tsx](../../../apps/web/src/ui/primitives/Selection.tsx) 及所属 CSS 定义，
通过方向属性复用；全局或页面覆盖样式必须遵守相同几何约束。

统一外观不合并语义：路由导航使用 link／`aria-current`，局部同级视图使用
`tablist`／`tab`／`tabpanel` 与方向键，普通偏好选项仍使用其选择语义。
主题卡片、复选框和开关继续表达各自的选择／开关状态，不人为加上导航指示条。
固定且不超过四项、文字简短的互斥偏好与筛选，使用内嵌式分段单选：共享圆角底座、4px 内间距、图标与文字居中，
选中块用中性表面、细轮廓和轻微阴影表达层次；不加导航指示条。
外观模式按“系统／浅色／深色”排列，系统选项的完整可访问名称为“跟随系统”；
使用 radio 语义、方向键及 Home/End，选中项作为唯一 Tab 入口，触控高度至少 44px。
长名称、需要展开说明、超过四项或会增长的成员／会话等选项继续使用 Select，
不根据当前结果暂时少于四项就改变控件类型。分段控件测量等宽单行所需宽度，
窄屏放不下时回退共用 Select；不截短标签、不强制折行，不改选中值、草稿或保存时机。
独立布尔开关、多选和页面导航保持对应的交互语义。

列表／卡片视图也属于局部模式，使用紧凑分段控件，保留两个清楚的图标和文字入口，
不拉伸成长条。邮件加密、会话／话题提醒与成员类型等短选项使用相同规则。
分段组放在非模态筛选弹层时使用 dialog／popover 语义；不能把 radiogroup 塞进动作 menu。
同一弹层的长角色列表可以保留独立的 menu／menuitemradio 和其键盘导航。

### 开关与图标按钮的实际居中

- 命中区固定 44 × 44px，无默认内边距，不被 flex 挤压。
- 轨道 44 × 26px，在命中区垂直居中；轨道定位到按钮，圆点定位到轨道，使用同一坐标关系。
- 圆点 20 × 20px，上下与当前端边缘各留 3px；行程为 `44 - 20 - 2 × 3 = 18px`。
- `role="switch"`、`aria-checked`、可访问标签与键盘操作共同表达状态。
- 新密度、主题、disabled、字体和布局不能改变上述几何关系；状态改变不依赖颜色或动效。

图标按钮清除浏览器默认内边距，使用 flex／grid 居中并禁止收缩；内部包裹元素也必须承接
完整的居中区域，SVG 不依赖文字基线定位。关闭 X、侧栏按钮、头像回退文字和退出登录按钮
均使用真实边界验收，不能只检查外层 `align-items` 或截图存在与否。
退出登录使用统一危险按钮、控件圆角与稳定命中区，不能保留浏览器方形按钮。
居中与开关间隙通过正式组件的渲染边界测量，覆盖主题、密度、禁用、RTL 和窄屏。

### 消息表面与连续短消息

本人消息使用所属会话的语义浅底，他人消息使用中性内容表面；两者在五套主题的浅深模式中
都要可区分。姓名、头像、时间和 Bot／系统身份继续提供独立信息，不能只靠颜色认人。

连续消息保留独立 DOM、消息 ID、选择、回复和操作，只合并视觉表面。相邻消息须同时满足
相同作者 ID、作者类型和本人归属，同一本地日期且时间顺序有效，间隔不超过五分钟。
回复（包括尚未加载的引用目标）、隐藏、撤回、系统消息和未读分隔均打断分组。
这些边界由 [message-grouping.ts](../../../apps/web/src/features/conversation/message-grouping.ts) 统一计算，
群聊与话题不各写一套。

组首保留顶部圆角和完整身份信息，组中上下边缘平直，组尾恢复底部圆角；组内紧凑衔接、组间留白。
不能让每条短消息独立圆角产生连续锯齿边，也不能把整组变成不可单独操作的大消息。
单条 hover／focus 只强调该条，不改相邻圆角、组边界、头像槽位或阅读位置。

消息行内工具直接融入消息表面：容器透明、无白底工具条、无重阴影；需要时显示轻量按钮反馈。
桌面 hover、键盘、右键和手机长按／更多共享当前消息动作，触屏入口不依赖 hover。
图片预览、引用、附件及表情继续使用同一富内容布局，不因消息短或属于话题而简化。

编辑器外层停靠区域保持透明、无整条底色和顶部分隔边；仅输入框本体有语义表面、圆角、细边与轻阴影，
形成悬浮输入感。回复、待发送附件、发送目标和失败信息按实际状态出现，不为装饰永久占空白区。
透明外围不意味着消息必须穿过输入框；正文滚动区和输入区仍保持安全的布局边界。

## 7. 动效规则

| 场景 | 参考时长 | 行为 |
| --- | --- | --- |
| 按压 | 120ms | 微弱反馈，不能位移命中目标 |
| 新增内容反馈（可选） | 180ms | 只作用于新增项，不重播历史消息 |
| 详情进入 | 200ms | 表达空间关系；关闭可更短 |
| 开关 | 160ms | 圆点短程移动；中断后仍显示真实状态 |
| 减少动态效果 | 0 或必要的即时状态替换 | 不延迟任务完成，不自动平滑滚动 |

避免全局 `transition: all`。需要持久的进度、失败或只读信息留在原位置，不能只用消失的 Toast 表达。
窗口或主题改变不重播入场动画，键盘用户不等待动画才能聚焦。
