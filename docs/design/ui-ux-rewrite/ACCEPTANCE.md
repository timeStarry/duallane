## 1. 六条关键任务

以下场景使用虚构内容、独立浏览器上下文和可丢弃测试数据。每项记录实际提交、
环境、结果与证据；“计划”“未运行”和“通过”必须区分。

### U01：从入口建立一场可用会话

1. 从入口选择私密直连，填写昵称并创建；直接进入等待中的会话，不额外要求“进入聊天”。
2. 编辑等待草稿，用第二个浏览器打开完整邀请并加入；连接状态连续更新，第一端草稿、
   焦点与会话不重建，未发送的等待草稿不被自动发送。
3. 覆盖缺少密钥、无效／不可用房间、连接失败及重试；给出有效下一步，不能误示成功。
4. 另起隔离场景进入共享空间，覆盖登录、回调、有效邀请、过期／撤销／重复邀请、
   未获准身份及 `WORKSPACE_ENABLED` 非精确 `true` 的不可用状态。

通过条件：两通道入口、页面标题与保存说明一致；直连不要求空间账号；登录或邀请失败
不泄露资源；入口重排不改变任何鉴权请求、回调和浏览器专有秘密的去向。

### U02：发送文件后安全结束私密直连

1. 两端发送文本、多行中文及文件，检查消息确认、接受／拒绝、传输、校验与保存状态。
2. 有未保存内容和进行中传输时，分别请求返回入口、切换通道和新建直连；选择“继续会话”。
3. 验证取消决策前后连接仍可收发，任务未被中止，未先发送 `leave` 或销毁通道。
4. 分别覆盖本机保存成功、存储失败、导出选择器取消、明确放弃并结束；失败保留当前内容，
   放弃后临时内容按契约清理，未完成传输不显示成功。
5. 模拟对方离开、临时断网及浏览器刷新／关闭；区分可重试断开与结束，不承诺关闭前
   一定提示或保存，不从服务端恢复私密内容。

通过条件：保存范围与文案相符；浏览器存储或导出文件中不混入邀请密钥；不保存的 P2P
消息、文件正文不进入服务端存储、日志、共享空间或主题偏好。测试记录能证明取消退出
之前没有实际结束副作用，不能只检查弹窗消失。

### U03：群聊、话题与草稿不误投

1. 在群聊编辑未发送正文、回复和附件，打开已有话题；先导航到话题页，原草稿留在群聊。
2. 目标话题已有草稿时不覆盖、不合并；返回群聊恢复原草稿和阅读位置，再回话题恢复
   话题自己的草稿与位置。群／话题阅读游标独立。
3. 用新建话题表单创建，再用合法 `#[标题](正文)` 快捷语法创建；各产生唯一话题、
   首条消息与群创建卡。覆盖校验失败、重复提交和响应重放。
4. 发送话题消息，默认只进入话题；显式同步到群聊、取消同步遵循既有投影规则。
5. 覆盖未加入、已关闭／归档、成员撤权、发送失败、重试及切换目标期间的迟到响应。

通过条件：输入框附近始终能确定发送目的地；重试仍投递原目标，旧响应不清除新草稿；
不支持的附件或命令有准确说明，不显示虚假的通用能力。话题选择本身不隐式发送、加入、
搬运草稿或同步到群聊。

### U04：找到文件并完成一次受控传输

1. 分别从文件库、会话附件和可用详情打开同一文件；核对来源、状态、可用操作和返回位置。
2. 使用会话／话题筛选、成员与文件查找；无结果、服务失败、加载中及撤权状态文案准确。
3. 在上传或下载中切换聊天、文件、主题和窗宽；同一任务状态连续，不重新发起传输。
4. 覆盖额度临界值、超额、并发争用、取消、失败、重试、重复完成、文件失效和访问撤销。
5. 来源存在且可访问时定位到可支持的来源；无原消息定位能力、独立文件或来源不可访问时
   不提供误导链接。

通过条件：超额在接收传输前被服务端拒绝；上传／下载按同一现行额度规则计量；重试不
重复文件或绕过计量，UI 稳定任务身份不篡改服务端尝试记录；搜索不宣称检索历史全文
或文件正文，不暴露未授权对象。

### U05：普通成员、管理员与 Bot 使用同一界面

1. 以普通成员、管理角色、只读／受限角色分别访问导航、成员、群详情与空间设置。
2. 完成实际角色允许的邀请、成员管理、群管理和既有 Bot 配置／授权操作；界面与
   服务端权限一致，危险操作明确对象与结果。
3. 在表单打开和请求进行中撤销权限，注入迟到响应／重复事件；撤权后不恢复受限数据。
4. 检查 Bot 身份、卡片 fallback、无效命令、令牌单次展示及撤销／失效反馈。
5. 检查容量、历史保留和既有管理信息；不把仅有后端记录的能力凭空呈现为完整管理 UI。

通过条件：无客户端隐藏代替授权；权限失败不泄露存在性；敏感拒绝产生领域要求的
无内容审计；令牌不进入 URL、聊天、遥测或日志。共享组件不扩大 Bot 或话题的权限。

### U06：切换偏好和屏幕后继续原任务

1. 处于阅读历史、编辑草稿、查看详情和进行中任务时，依次切换五套主题、浅／深／随系统、
   舒适／紧凑、动态和透明材质偏好。
2. 从桌面进入平板和手机布局，打开详情再返回；会话、话题、草稿、滚动锚点与未读保持正确。
3. 用键盘完成导航、筛选、编辑、菜单和弹窗；验证焦点顺序、Escape、安全确认和焦点恢复。
4. 修改既有通知级别和邮件／ntfy 渠道设置，覆盖保存中、失败／重试、权限拒绝和事件
   重放；检查邮箱验证、订阅配置及轮换流程。浏览历史时新消息仅提示，不强制滚底。
   主题变化不更改通知授权或未读。
5. 真机打开软键盘，验证输入区、发送按钮、安全区域、返回与横竖屏；不依赖悬停。
6. 按 [对象操作与设置专项](CONTEXT_AND_SETTINGS.md) 检查右键／长按／更多／Shift+F10 的适用动作、
   原生文字与链接选择、移动／滚动／第二指针取消、松手不执行、菜单边界和焦点恢复。
7. 编辑资料后分别切换类别、返回父级和使用浏览器返回；继续编辑不丢输入，保存并离开只在成功后导航，
   放弃修改不撤销旧保存。快速修改、迟到保存响应及失败重试不覆盖最新输入或串账号。

通过条件：无页面闪烁、跳转目标变化、未提交输入丢失、焦点丢失或内容遮挡。
系统减弱动态优先；关闭透明效果有实色替代；外部通知渠道不可用时仍可使用应用内反馈。

## 2. 完整状态矩阵

覆盖清单中每个异步页面、面板和命令都标注以下状态。没有适用含义的单元格注明原因，
不能用“只有成功截图”代替状态设计。下表是逐项检查要求，不表示已经执行。

| 状态 | 界面与用户操作 | 行为／数据断言 |
| --- | --- | --- |
| 初次加载 | 稳定骨架、可理解的等待状态 | 不提前展示其他会话或上个账号的数据；无明显布局跳变 |
| 加载中已有内容 | 保留可用内容与当前位置，标明刷新／重连 | 不覆盖草稿，不因后台刷新重置已确认状态 |
| 空内容 | 说明当前对象，提供实际可用的下一步 | 空态与无权限、未加载、查找失败分开 |
| 正常有内容 | 短长混合、中文、URL、图片、文件、回复、卡片 | 长内容不溢出；不受信任输入按既有清理规则显示 |
| 正在提交／传输 | 稳定原对象和进度，必要时允许取消 | 重复点击不重复写入；主题／导航不重启任务 |
| 成功 | 就地确认，保持新输入与阅读锚点 | 以领域确认结果为准；P2P 接收不误写成服务器已保存 |
| 可恢复失败 | 原内容、失败原因和针对性重试 | 重试原目标；旧失败或成功不能覆盖更晚状态 |
| 离线／重连 | 保留当前内容，说明仍可做什么 | 无明文降级、不冒充已投递、不自动发送未提交草稿 |
| 无权限／已撤权 | 安全提示、移除不可用操作或内容 | 服务端拒绝；缓存与迟到响应不得重泄露受限数据 |
| 功能未启用／能力不支持 | 明确不可用原因与可行替代 | 不伪造功能，不改变 Workspace 默认禁用规则 |
| 冲突／重复／迟到响应 | 保留未提交工作，允许刷新确认 | 维持 revision、幂等、事务和请求代际防护 |
| 结束／删除／归档／过期 | 明确终态和仍可执行的动作 | 不恢复失效资源；保留策略、引用和审计不被 UI 清理改写 |
| 取消／破坏性确认 | 明确对象、后果，默认可安全返回 | 取消无提前副作用；确认后任务与连接真实结束 |
| 偏好保存失败 | 保留选择并说明是否生效，提供重试 | 不假示服务端保存；失败反馈不与本地预览状态混淆 |

消息专项至少覆盖：文本、中文 IME、换行、纯提及、表情、回复、长消息、图片、文件、
未知卡片与 Bot 卡片；按目标实际能力选择。状态变换同时检查键盘焦点、读屏名称、
必要的 live region 与视觉反馈，避免连续重放反复打断读屏。

| 主题契约异常 | 未知主题、不支持 schema、缺失必需语义值与加载失败按设计系统回退／拒绝策略处理，无空白或不可读界面 |

只是证据的一部分，不能取代实际完成任务。

## 4. 安全、隐私、兼容性验收

依据 [Security and data](../../development/SECURITY_AND_DATA.md)和现有领域协议，
检查以下可观察结果；不能只根据文案推断后端安全。

| 边界 | 可验收证据 |
| --- | --- |
| P2P 浏览器密钥 | 使用合成邀请秘密检查 API、信令、遥测和服务端日志中不存在 `#k=` 值；重定向、复制公开信息和错误报告不外发秘密 |
| P2P 内容 | 两浏览器文本／文件测试及 Go 隐私测试证明服务器不持久化正文或文件；回退只发送经验证的安全信封，不降级明文 |
| Workspace 开关 | 对未设置、`false`、拼错值和精确 `true` 验证当前启用／拒绝契约 |
| 当前权限 | 角色、空间／群／话题成员、Bot scope／grant、撤权及直连资源请求均在服务端校验；禁用控件不是通过证据 |
| 配额与并发 | 临界值、超额与并发传输在读取传输体前按现有规则拒绝；重复或去重不免除应计量字节 |
| 审计与日志 | 域要求的敏感失败有无内容审计记录；令牌、正文、文件字节、密钥、签名访问 URL 不进入日志或通用提示 |
| 数据与协议 | 同一既有账号、会话、话题、附件、未读及偏好在新界面可用；话题 API 的兼容新增字段遵循领域契约，不移除旧字段或改写历史消息；保留、幂等和并发边界通过真实 Go 回归 |
| 引用与失效 | 文件、回复、话题同步卡的删除／保留／撤权安全降级；不存在为修复预览而绕过对象权限 |
| 内容渲染 | 不受信任的名称、消息、文件名和卡片不能执行脚本；CSP、响应头、脱敏与同源约束不弱化 |
| 偏好隔离 | 主题记录只包含适用偏好，不夹带会话内容或秘密；换主题不改身份、权限、通知授权或消息目的地 |

没有协议变化就不增加数据库迁移。若实施证明需要变更持久化结构、公开 API 或偏好保存
范围，先更新领域契约与兼容／迁移测试，不能把它当作纯样式改动带入。

## 5. 正式产品门禁

0.18.0 在线能力由 Go 拥有。默认 `pnpm test:e2e` 是 Go P2P 浏览器路径，不能证明
Workspace 登录、导航、权限或持久化正确。后者使用显式 PostgreSQL 的 Go Workspace
浏览器门禁；不得启动退休 Node API、隐式 SQLite 替身、自动迁移或生产数据库补证据。

| 门禁 | 本轮全量产品重写的要求 |
| --- | --- |
| 前端与行为 | 对受影响行为的 Vitest／组件测试、聚焦 Playwright、`pnpm lint`、`pnpm build`，桌面与 390×844 视觉审查 |
| 安全关键行为 | 重写涉及 P2P、Workspace、鉴权、配额或实时状态时运行 `pnpm test`，并覆盖失败、重复、撤权和并发 |

## 6. PR 与发布判定

本次 PR 同时提交正式实现与规范：核对相互链接、覆盖范围、规范与实现的差异、主题契约、
安全边界和 `git diff --check`，并执行上述受影响门禁。实际结果由 [PR 验证记录](PR_VERIFICATION.md) 记录；本验收要求表不预填“通过”。
HTML 原型可证明局部材质、布局和演示交互，不能证明全部真实页面、后端、事务、
对象授权、持久化、真机或读屏验收已完成。

产品正式发布必须同时满足：

- [交付契约](DELIVERY.md) 要求的正式组件库、同源工作台、实际架构与页面族设计调整记录齐全；Demo 只作方向参考，原型代码和模拟成功不进入正式业务路径。
- COVERAGE 全部适用页面与状态已使用新设计，U01–U06、主题矩阵及必要技术门禁有证据。
- 没有新旧语言并存、旧 CSS 降级或未完成页面；同一可用能力在不同会话中不回退。
- 所有未运行的必要检查已补齐，不能用“未发现问题”掩盖环境缺失。
- 切换与整版回滚遵循现有发布控制、兼容检查和 Go 部署流程；运行时不提供两套 UI 切换。
- 由仓库规定的维护者完成最终合并；部署另按明确授权和正式发布程序执行。

内部可以分工提交、验证和修复；上线单位是完整的新体验。回滚恢复已知可用发布版本，
不是为部分新页面加载 legacy CSS，也不恢复退休在线服务。
