但交付不能混用新旧页面、保留旧 CSS 降级路径或长期旧组件兼容层。
已有 API、消息协议、数据、权限、配额、保留及审计语义保持兼容；任何超出已有协议的
能力先完成领域设计，再单独决定是否纳入产品范围。

## 2. 导航与设置归属

共享空间的一级导航为 **聊天、话题、文件、成员、个人**；owner/admin 增加“空间”，
其余角色不显示“空间”一级入口；预留 auditor 也不因导航获得内容或管理能力。
进入哪个对象，标题、列表选中、正文与详情就共同表达哪个对象。
没有选中对象时，不显示上一次会话的详情。导航精简不删除有效深链接：普通成员访问旧空间链接
仍按服务端能力显示可见摘要或安全受限状态，不因此获得管理权限。

| 入口 | 所有内容的归属 | 不应混入 |
| --- | --- | --- |
| 一级导航“个人”／个人设置 | 个人资料、聊天偏好、外观、通知、表情、自己的 Bot 与授权等既有能力 | 空间整体的权限、容量和保留策略 |
| 管理导航“空间”／空间设置 | 空间信息、角色成员、邀请、容量、保留及当前角色可用的管理能力 | 仅影响自己的主题或通知偏好 |
| 私密直连标题／连接详情 | 当前连接、邀请、验证与传输相关信息、当前会话的本机保存 | 共享空间身份、成员管理或云端历史 |
| 共享空间连接状态 | 当前空间服务连接、重连与恢复反馈 | 私密直连邀请或密钥 |

普通成员与管理员使用相同布局；权限决定可用操作，不产生第二套视觉语言。
服务端仍负责每次授权。不可访问资源使用安全错误文案，不通过导航、搜索建议或空态
泄露资源是否存在。关闭详情只返回当前对象；返回列表不等于退出空间或结束直连。

用户菜单只保留配额摘要、重新同步、返回入口和退出登录，不重复“个人”、空间入口或设置分类。
手机个人设置首页也提供独立退出入口，避免需要桌面悬停菜单才能完成账号操作。
“返回入口”与“退出登录”具有不同后果，不互相替代；两者涉及未提交内容时均先完成离开决策。

只有聊天和话题具有可折叠中栏。桌面折叠按钮占据固定导航槽位；文件、成员、个人和空间没有中栏时，
保留该按钮的位置并禁用，给出“当前视图没有中栏”的可访问说明。不能删除槽位而使日常导航上下跳动。
折叠只改变列表可见性，不切换目标、不清空草稿，也不关闭原本有效的消息操作。

桌面用户可拖动中栏右边界调宽；方向键每次调整 16px，Home／End 到当前最小／最大宽度，
Enter 或双击恢复当前断点的默认宽度。拖动中 Escape、指针取消或窗口失焦恢复拖动前宽度。
确认后的宽度只存于本浏览器设备，聊天和话题共用；窗口变窄或展开详情时临时收敛，恢复空间后
恢复用户宽度，不覆盖其偏好。存储不可用时当前页面仍可调节。尺寸、边界与断点只在设计系统定义。
调宽不重建编辑器、不改变选中会话、草稿、消息身份或阅读状态。

## 3. 私密直连：从等待到结束保持同一上下文

### 3.1 创建与加入

填写必要信息并创建成功后，直接进入会话界面。正文中的等待状态提供完整邀请链接的
复制与安全说明，标题显示“等待对方加入”，编辑器位置提前稳定。
无需再点击一次“进入聊天”。连接建立时就地更新状态，不重建会话、不清空草稿、
不把阅读位置或焦点突然移到别处。

等待时可编辑本地草稿；未具备发送条件时明确说明原因，不假装消息已发送，
也不在恢复连接后未经用户发送动作自动投递等待草稿。邀请无效、缺少密钥、房间不可用
和暂时网络失败分别提供当前可行操作，不能把可重试失败描述为内容已永久丢失。

连接状态与内容保存状态分开：连接成功不代表内容已保存；传输完成也不代表文件已写入
用户设备。保留现有协议的确认、校验、失败与可重试条件。

### 3.2 应用内离开与结束

“返回入口”“切换通道”“创建新直连”“结束会话”等会丢弃当前上下文的动作，
统一进入同一个退出决策；普通详情返回不触发它。

| 用户动作／状态 | 目标行为 |
| --- | --- |
| 有未保存内容或未完成传输时请求离开 | 显示明确对象与后果：未保存内容的去向、未完成传输会中止；提供“继续会话”和明确结束选项 |
| 取消退出／按安全的 Escape 返回 | 保持原连接、定时器、传输任务、草稿与消息；不得先发 `leave`、关闭通道或清空状态再询问 |
| 选择保存后结束 | 说明保存位置与范围；本机保存成功后再完成结束。保存失败或保存选择器取消时保持当前内容，允许重试或明确放弃 |
| 明确选择不保存并结束 | 结束连接、清理临时内容；未完成任务变为已中止，不能停留在“传输中”或变成“成功” |
| 对方离开或连接中断 | 就地说明状态与恢复条件，保留仍在本页的可保存内容；“暂时断开”与“本次会话已结束”分开 |
| 会话已经结束 | 只提供仍然有效的保存／导出、关闭和新建动作，不承诺重新连接会恢复被丢弃的内容 |

结束是显式操作，执行后不能通过“取消退出”复活旧连接。确认期间持续到达的消息与
传输结果仍按当前会话处理；保存范围和未保存标记不能使用已经过期的快照。

### 3.3 保存与浏览器关闭边界

“保存到本机浏览器”与“导出文件”是不同动作。沿用当前本机保存的真实存储方式与
数据范围，并明确本机浏览器记录不等于服务器备份。文件二进制是否包含在记录中
必须以实际序列化契约为准；不能把会话记录导出描述为所有附件均已备份。

刷新、关闭标签页、进程被系统终止时，浏览器不保证执行自定义确认、异步保存或清理。
可以使用平台允许的离开提示，但不能承诺“关闭前一定提示”“一定保存”或“下次自动恢复”。
关键保存操作应在会话内始终可达。没有用户选择，不将 P2P 内容转存到共享空间、
新主题偏好存储或任何服务端存储。

## 4. 话题：入口显式，发送目标明确

### 4.1 新建话题

群聊详情与话题列表提供“新建话题”入口，表单显示所属群、标题、正文及必要说明。
标题和正文沿用领域校验；提交进行中避免重复创建，失败保留输入。成功后进入新话题，
群聊中的创建卡继续来自既有领域事件与幂等规则。

保留 `#[标题](正文)` 作为熟悉用户的快捷方式。它继续遵循服务端既有的 human、group、
纯文本、非回复等解析条件；界面不能把不符合条件的文本擅自转换成话题。
表单与语法入口使用同一领域创建能力，不能产生额外的原文消息或两张创建卡。

### 4.2 选择已有话题与草稿

从群聊选择已有话题时，先进入该话题的独立页面。标题与编辑器目标明确显示话题名称
和所属群；不能只改变原群编辑器内部的 `topicId`，让用户仍以为在给群聊发消息。
该选择也不能自动发送、自动加入、自动复制草稿或自动同步到群聊。

草稿默认留在原目标。群聊正文、回复对象、已选附件，以及话题正文和回复对象分别保留。
话题页先恢复自己的草稿；即使目标话题已有草稿，也不覆盖或合并。
本轮不提供自动“搬运草稿”捷径：用户需要带走文字时，可以明确复制，在目标页粘贴，
再检查发送目标；附件和回复关系不得静默跨目标搬运。

提交内容成功进入待发送队列时，即从编辑器释放本次提交的内容与回复关系，允许用户在附件
后台上传期间继续编写和发送下一条；未随本次提交发送的草稿保持原样。成功回执只更新
对应的待发送项，不清除或覆盖当前的新草稿。失败内容留在原消息供显式重试，保留原内容、
已上传附件与原始目的地；重试不能随当前选中会话变化而改投，也不能覆盖新输入。

话题消息默认仅进入话题流；现有“同步到群聊”是可辨认的显式选择，保留权限、事务、
唯一投影与取消同步契约。不能通过新视觉把同步描述为默认复制正文到父群。

### 4.3 紧凑横幅与按需详情

默认话题页优先显示消息和完整编辑器。标题、状态和紧凑横幅共同标明话题、所属群、参与人数与
“话题详情”入口；横幅不常驻完整描述、提醒选项或关闭／归档等管理按钮。
长标题按设计系统处理，不挤走返回、状态和必要操作。

“话题详情”按需打开：桌面为右侧详情抽屉，手机为完整详情层。其内部按简介、提醒、参与、管理
分组，承载完整描述、创建信息、所属群、提醒方式以及当前对象允许的加入、退出、关闭和归档。
详情默认关闭，不长期遮挡或压缩编辑器；关闭、Escape 和安全的遮罩关闭后回到触发入口，保持草稿和阅读位置。
切换话题或账号立即关闭旧详情，旧操作结果不得落入新话题。

未加入者只显示服务端允许的摘要与加入入口，不显示话题正文或可发送编辑器；关闭／归档的话题呈现
明确只读状态，不提供假发送、回复、表态、常驻或撤回入口。个人隐藏／恢复等可读范围内的个人操作
仍以实际能力为准。参与和管理按钮按成员关系、创建者、角色、状态及服务端授权生成，不能由标题或
“管理员”外观推断权限。加入话题不是自动发送，也不是自动授权 Bot 读取上下文。

## 5. 返回、阅读状态与多端布局

每个会话与话题分别维护选中对象、草稿、回复上下文、阅读锚点／偏移和新消息提示；
列表筛选按所在视图维护。详情是否打开服从对象作用域，话题详情不跨话题沿用。
状态至少在当前已登录页面会话中成立；刷新恢复、本地持久化
和跨设备同步不在没有协议设计时自动扩展承诺。

从群聊打开话题，再返回群聊，恢复群聊先前阅读位置；话题自己的阅读位置单独保留。
浏览历史时收到新消息不强制滚底，提供“回到最新”；用户主动发送的有效内容进入待发送队列后，
立即回到该目标的最新消息，附件无需等待上传完毕。若当前显示引用定位的历史窗口，恢复最新时间线，
不能仅滚到旧片段末尾；无效提交不改变位置，延迟结果不能拉走已经切换到其他会话的用户。
只为满足既有可见性与阅读条件的
目标更新读游标。打开详情、切换主题或调整窗宽不视为读完后台内容。

| 窗口形态 | 列表、内容、详情关系 | 返回与状态 |
| --- | --- | --- |
| 宽屏 | 列表和内容常驻，空间足够时并列详情 | 详情可收起；保持可读正文宽度，不压缩成狭窄聊天栏 |
| 平板／中等窗口 | 列表和内容并排，详情覆盖 | 关闭详情回到原内容；旋转／分屏不改目标 |
| 手机／窄窗口 | 一次一个主窗格，按列表→内容→详情进入 | 返回先关闭覆盖层，再回上一级；草稿和位置按目标恢复 |

文件和成员只保留一个主列表，不在中栏再复制相同内容。桌面详情正文独立滚动；手机详情为完整页面，
标题、关闭／返回和操作始终有明确归属。文件／相册的列表和卡片是同一结果集的两种展示方式，
使用紧凑的图标加短标签分段单选，不用导航 Tab，不拉成细长的满宽按钮；切换保留查询、对象与任务。

断点、宽度和触控尺寸见 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)。布局按窗口可用空间
变化，不按设备名称硬编码。移动端软键盘、安全区域、系统返回和长标题均需要真机验证；
必要操作不能只在悬停时出现。

## 6. 共用输入与消息语义，保留能力边界

右键、长按、可见“更多”与键盘共用动作的对象范围、原生选择保护、焦点和确认规则，
按 [对象操作专项规格](CONTEXT_AND_SETTINGS.md) 实施。菜单只负责呈现适用能力，不扩大通道权限。

Workspace 私聊、群聊和话题使用同一个完整会话组件与编辑器，包括消息渲染、结构化卡片、附件、
回复、提及、表情、表态、对象菜单、常驻、撤回、个人隐藏、发送进度、失败重试和阅读反馈。
Bot 消息经同一消息呈现链路处理。话题不能拼装一套看似相同、实际缺少附件或消息动作的简化聊天页；
共享的是完整交互与领域命令接口，具体对象是否允许执行仍按下表和实际 capability 决定。
P2P 可复用视觉和适用的编辑行为，其传输、内容保存和会话生命周期保持独立。

| 共用语义 | 需要保留的差异 |
| --- | --- |
| 编辑、换行、IME、焦点、有效提交 | 各域实际支持的消息块、附件、命令和长度限制不同 |
| 作者、时间、回复和操作菜单 | Bot 身份、成员角色与可操作范围明确；不把自动化身份伪装成人 |
| 待发送、发送中、成功、失败、重试 | Workspace 以领域提交结果为准；P2P 以对应消息／传输确认状态为准，不混用“已保存” |
| 文件预览、进度与任务反馈 | P2P 接受／拒绝和接收校验不等于空间上传；空间受服务端权限和配额控制 |
| 内容更新和引用定位 | 话题关闭／未加入／归档、撤权、过期、未知卡片有明确受限状态 |

话题附件沿用正式上传和消息提交链路。暂存上传不因完成而变为父群全员可读；消息关联后的读取
仍受话题、群与空间有效成员关系、消息状态、额度和保留规则约束。退出或被移出后不能借附件 URL、
父群文件列表、常驻列表或事件投影读取原本无权查看的话题内容。同步到群聊按独立投影契约处理。

连续短消息按稳定作者身份、时间与边界分组，采用整组首尾圆角、组内无缝、组间分隔的呈现；
具体尺度见设计系统。同名不同 ID 不合组，日期、未读分隔、回复关系、隐藏、撤回和系统消息形成边界。
分组只改变相邻边缘，不合并消息身份；每条消息保留自己的复制、回复、反馈、菜单和焦点目标。
被动追加或加载历史不能因分组重建已有消息节点，也不能将阅读中的用户拉回最新；
主动提交入队按前述明确的发送后回到最新规则处理。

消息行内工具栏采用透明底面，与单条消息关联；不叠加有色悬浮面板。编辑器外围底部区域保持透明，
只有输入器本体承载有色浮层，普通会话和话题使用相同规则。触控、键盘、移动安全区以及关闭透明材质
时仍有清楚的操作入口和可读内容，不能以透明样式掩盖禁用、发送中或失败状态。

未知卡片使用契约中的安全 fallback；不为了统一卡片外观绕过内容清理。发送、重试、
重复事件、旧请求返回和 React Strict Mode 不得产生重复消息、丢草稿或页面闪烁。

## 7. 搜索、文件、通知与个人偏好

### 7.1 搜索准确描述范围

| 位置 | 目标文案与结果范围 |
| --- | --- |
| 会话列表 | “筛选会话”；只检索已加载会话的名称、成员和现有摘要等可用字段，不承诺搜索历史消息 |
| 话题列表 | “查找话题”；按已有话题源的标题、所属群和发起人筛选，不承诺检索全部话题正文 |
| 成员 | “查找成员”；按现有服务端查询和可发现性规则返回，不泄露不可发现身份 |
| 文件 | “查找文件”；依据文件查询的实际名称、来源等字段，不宣称搜索文件内部内容 |

搜索失败保留查询并提供重试；无匹配说明当前范围。未加载、不具备权限和确实为空不能
用同一句“没有内容”掩盖。过滤条件、结果计数和返回位置按所在视图保留。

### 7.2 文件来源与稳定任务

文件详情提供名称、分享者、来源、可用状态及有意义的权限／额度信息。
存在可访问来源会话时提供“打开来源会话”；只有现有契约能定位具体消息时才展示
“查看原消息”。来源已删除、保留到期、不可访问或独立上传时，使用相应安全说明，
不生成失效按钮，不暴露内部对象 ID、哈希或存储路径。

上传、下载和 P2P 传输都以稳定任务身份展示状态；切换导航或主题不会复制、重开或取消
同一任务。取消、失败、重试及完成就地更新。重试遵循现有协议的幂等及新尝试规则，
不得为了保留一行 UI 而误复用已经终结的服务端传输记录。

空间传输前呈现服务端权限与剩余额度检查结果；上传与下载合计按现有契约计量。
额度拒绝发生在接受传输前，界面校验不能替代服务端检查。不能用去重、缓存或预览
绕过应计量的访问。

### 7.3 未读、通知与外观

个人设置的桌面固定分类／右侧内容、手机逐级页面、资料显式保存及未提交修改离开规则，
见 [个人设置专项规格](CONTEXT_AND_SETTINGS.md)。目录重排保留既有深链接和有效返回目标。

未读标识与“只提醒提及／全部提醒／关闭”等既有提醒级别按当前域语义区分。
主题变化不改变未读数量、关注对象、通知授权或音效选择；切换会话、打开详情和收到
重放事件不能重复累加未读。人在阅读历史时保留位置和新消息入口。

个人设置固定为个人资料、外观、聊天、通知、隐私、表情、Bot 与连接七类；退出登录是独立操作，
不构成第八类。主题、浅深／随系统、密度、
动态与透明材质分别设置，语义 Token 契约见设计系统。普通偏好可延续既有自动保存模型，
并显示正在保存、已保存、失败／重试；邀请、授权、令牌操作和删除仍为明确命令。
现有邮件通知与通过 ntfy 客户端接收的移动推送必须完整保留，包括邮箱验证、渠道状态、
订阅配置与凭据轮换；通知内容继续遵循现有不含正文的边界。如果后续提供浏览器原生
通知，仅在用户明确操作时申请授权，拒绝后不反复弹出。不能把浏览器授权开关当作
邮件／ntfy 的控制，也不能把新增原生推送能力假装成已实现。

主题选项使用真实 Token 绘制微型产品窗，单行横向浏览，只显示预览、标题与选中标记；
拖动、触摸滑动和浏览箭头只改变浏览位置，点击或键盘确认才选择主题。明暗模式是独立分段单选，
不与主题家族合并。固定短选项、长选项及空间不足时的控件选择按设计系统统一处理。
资料的保存区独立于字段和只读身份，
通知的渠道、频率、地址、验证命令分层，帮助与保存状态按同类行对齐。

### 7.4 成员与管理任务

群详情按概览、话题、成员、文件和设置组织，由真实会话类型与权限裁定可见章节；其顺序、标题和内容
保持一致，不把所有管理表单堆在概览下。概览提供身份、摘要、常驻及必要跳转；成员页承载成员和邀请，
设置页承载资料、提醒和适用的低频群管理。关闭详情回原会话，切换对象不残留旧群资料或操作。

会话成员一行对应一个可见“更多”，与右键、长按使用同一动作定义。“邀请成员”打开独立成员选择器，
搜索实际候选、多选并确认，不要求用户输入内部 ID；权限与不可邀请原因仍来自现有能力。
提交复用单成员 API 串行执行，部分成功后只重试未成功项。切换账号、群或权限失效时中止后续
提交并忽略旧作用域响应；这是非原子操作，不能承诺取消会回滚已成功添加的成员。

所有设置内页按“常用信息／偏好→必要子页或章节→低频命令”的层级组织，不用连续嵌套卡片或弹窗
代替目录。Bot 在个人设置内按资料、连接、授权、凭据四个同级章节组织；setup 批准、单会话上下文授权
和令牌 scope 仍是不同约束，不将允许上下文解释为授权完整历史。Echo 需求与公开征集使用同级标签，
切换保留草稿；常用筛选直接可见，其余筛选按需展开，正文只保留一处主滚动。
空间信息、邀请、角色、可见范围、邮件和 Echo 等页面按现有能力显示，角色／可见范围使用搜索与扁平成员行；
自动关系、可修改授权和只读状态分开，切换查看者或账号不得串用迟到的权限结果。

## 8. 需要独立领域设计的候选

这些项目不是全量视觉重写的“已完成”能力，也不阻塞已有能力用新语言完整发布。

| 候选 | 纳入产品前需要明确 |
| --- | --- |
| 历史消息全文搜索／跨会话全局搜索 | 服务端索引、可见性过滤、保留／删除同步、分页、排序与资源上限 |
| 跨设备草稿／刷新恢复草稿 | 保存位置、账号隔离、冲突处理、过期、删除及敏感内容范围；P2P 不默认进入云端草稿 |
| 超出现有字段的文件原消息定位 | 来源引用和权限契约、删除／保留后的行为，不能靠暴露内部存储信息实现 |
| 新增浏览器／原生客户端推送、关闭页面后继续传输 | 与既有邮件／ntfy 的关系、平台权限、后台限制、隐私内容、失败恢复与用户可见承诺 |

本契约不增加上述 API、不迁移持久化数据，也不改动 Go 服务的在线所有权。
实施时如发现当前能力与领域文档冲突，应更新对应契约与验收，不能借样式重写悄悄改变产品。
