## 本轮依据实际场景作出的设计修正

1. 开关采用独立命中区和同一定位坐标系，44×26 轨道、20×20 圆点、两端 3px，避免原型圆点偏移。几何断言只允许浮点表示误差，不缩小实际命中区。
2. 手机只保留当前任务窗格。聊天及设置子页隐藏底栏，返回根页面再显示导航；桌面个人/空间设置使用完整主内容，不挤在聊天详情区。
3. 选择器区分短浮层与手机长列表选择页，后者允许搜索、空结果与明确取消；Safari 点击按钮不自动聚焦的行为由控件显式处理。
4. 插入较早消息时，响应到达后、DOM 更新前记录滚动快照，避免浏览器原生锚定与应用补偿重复累加。快照按会话、请求和列表元素校验并只消费一次。触发对象位置不变时菜单继续打开，用户真正滚动离开对象则关闭；正文仍保留原生选择。
5. 手机菜单先关闭模态层再恢复焦点，避免仍处于 inert 的触发器无法获取焦点。
6. 资料明确保存；偏好显示真实提交状态。失败保留草稿，旧账号的迟到结果不能覆盖新账号。浏览器返回与应用内退出都在副作用前处理意图。
7. 删除合集的取消不再代表另一种删除。命令确认失效时清除旧意图；账号变化后不能继续执行旧身份发起的确认。
8. 话题表单使用 JSON 字段与同输入幂等键。独立话题草稿不会与群聊草稿混用；未发送话题内容加入全局退出/刷新判断。创建成功优先打开新话题，不执行正在等待确认的旧返回意图。
9. Bot 授权直接承接已有 API 的真实限制：私聊/群聊分开，授权上限明确，Token scope 独立，未知状态如实显示。服务器错误保留输入供重试。
10. 可见范围响应绑定查看者、账号和请求代次。保存时锁定对象；重复选择同一查看者保留当前数据与未保存修改。

## 视觉、性能与未覆盖范围

已查看正式入口、聊天、个人设置、详情、P2P 等待/详情、话题表单的桌面和 390px 截图，以及三组深色主题。对象列表额外检查 320px/900px 的布局。截图均为合成内容。

使用相同依赖和 Vite 对 `ef51873` 与当前代码构建比较：基线主 JS 1,187.33kB / gzip 344.29kB，CSS 225.46kB / gzip 34.75kB。完整集成主 JS 1,260.56kB / gzip 370.96kB，CSS 261.03kB / gzip 39.21kB。这些是包体积，不是启动耗时或真实交互延迟。主 chunk 仍大于 500kB，后续领域按需加载值得继续处理，不能宣称本轮已经完成性能优化。

仍需发布前人工验收：实际手机软键盘与安全区域、系统辅助技术/读屏、200% 缩放的完整业务流程。Firefox/WebKit 当前覆盖基础选择交互，没有据此宣称全部业务 E2E 或所有浏览器一致。

覆盖账本的“已接入／待完整验收”表示正式页面使用新语言，不能等同于每行全部状态都通过。最终版本号、release catalog、维护者评审与部署按 [发布说明草稿](RELEASE_NOTES.md) 和仓库流程处理。
