# 清晰双轨正式前端：实现边界

日期：2026-09-11。本文描述当前分支中的正式代码；当前体验规则见 [规范入口](README.md)，提交验证见 [PR 验证记录](PR_VERIFICATION.md)。[页面精修](PAGE_REFINEMENT.md)、[会话一致性](CONVERSATION_PARITY.md) 与 [首轮验收](PRODUCTION_VERIFICATION.md) 仅记录相应阶段的调整和证据。
它不把设计原型、工作台中的合成数据或分支代码等同于已经发布的服务。

## 生产入口与依赖方向

```text
main.tsx
  ├─ initializeAppearance → AppearanceProvider
  ├─ ConfirmationProvider：可取消且绑定当前会话的命令确认
  ├─ App：既有领域状态、权限投影、路由及实时生命周期
  │   ├─ features/entry/EntryPage
  │   ├─ shell/WorkspaceShell + WorkspaceNavigation + useNavigationGuard
  │   ├─ features/conversation/useMessageActions
  │   ├─ features/conversation/WorkspaceChatPanel：群聊与话题共用消息行和输入区
  │   ├─ features/settings：资料、外观、通知、隐私、邮件配置
  │   ├─ features/members/MemberPickerDialog：候选搜索、多选及提交作用域
  │   ├─ features/topics：结构化创建、目标独立的草稿和回复
  │   ├─ features/bots：显式上下文授权与失败重试
  │   └─ WorkspaceTopics / Bot / Echo / 头像等领域视图
  └─ /__design：仅开发构建可达，直接导入正式组件

领域视图 → ui/primitives → ui/theme
设置页面 → 注入的 SettingsServices → 现有 API 适配
```

没有增加 UI 框架、状态库或在线 Node 服务。`App` 仍协调经过验证的会话、加密、
上传与权限逻辑；本轮已拆出独立主题、控件、导航、消息动作与个人设置。
不要据此将尚未进一步拆分的领域控制器描述为已经完全模块化。

共享 `WorkspaceChatPanel` 接收显示消息及有类型的正文、卡片、表情等渲染接口。
App 提供同一个完整 Workspace 会话适配，话题通过有类型的 `TopicChatRuntime` 接入。群聊与话题共享 `message-model`、`message-projection`、`message-content`、`message-commands` 和实际上传服务，不能再增加简化话题内容渲染器；共享组件不反向导入 App。
话题只增加上下文横幅、默认关闭的 `TopicDetails`、同步选项及领域菜单，完整契约见 [体验与流程](EXPERIENCE.md)及 [话题领域设计](../../WORKSPACE_GROUP_TOPIC_DESIGN.md)。

## 主题与控件

- 生产色值的唯一来源是 `apps/web/src/ui/theme/tokens.ts`，包含原色、苔原、暮色、米色、极简的完整明暗定义；偏好和工作台共同通过 `isThemeId` 校验注册项。
- `preferences.ts` 负责版本化偏好与旧 `duallane-theme-mode` 迁移；`store.ts` 处理存储失败、系统变化和跨标签更新。
- `appearance.ts` 将语义值映射到根变量。已有样式名如 `--ink`、`--relay` 仅映射到新语义值，没有旧配色分支。
- `AppearanceProvider` 使用外部存储订阅；换主题不以 key 重建页面或编辑器。
- `ui/primitives` 拥有 Switch、SegmentedControl、Select、Slider、SelectionItem/Tabs、ViewModeSwitch、按钮及对象菜单。组件不读取会话或自行判断服务器权限。导航与互斥偏好使用不同语义；控件选型统一遵循 [设计系统](DESIGN_SYSTEM.md)，长选项与空间不足使用 Select。
- 外观页的 `ThemePicker` 直接使用正式主题 Token 绘制微型导航、消息和编辑器预览，预览明暗跟随当前解析模式；标题卡片沿单行滚动，触摸、鼠标拖动、浏览按钮和键盘均可到达全部主题。浏览不选择，确认后的选择与明暗、密度等偏好独立。
- 图标按钮使用居中的 `inline-flex` 命中区；`ViewModeSwitch` 是带图标与标题的两项 `SegmentedControl`，不再用两个独立方形按钮。组件尺寸和文件卡片布局以 [设计系统](DESIGN_SYSTEM.md) 为准。
- Select 的选择和取消由组件管理。手机长列表使用独立选择层，短列表使用浮层；日期、文件选择等适合系统能力的控件继续使用原生入口。
- `styles.css` 保留文档基础、壳层及既有领域布局，共用控件与设置、话题、Bot、Echo 局部样式由各模块管理；`ui/styles/README.md` 记录职责，不是第二套样式实现。

组件 API、键盘规则、FormData 行为和工作台命令见 [组件说明](../../../apps/web/src/ui/primitives/README.md)。

## 导航与状态

日常导航为聊天、话题、文件、成员、个人；owner/admin 额外显示空间，普通 member/guest 呈现为五项。
这是入口投影，不是新的授权机制；旧空间深链接保留按服务端能力显示只读摘要或安全受限状态的兼容。
桌面使用窄导航轨；只有聊天和话题保留可折叠的中间列表，折叠不清除草稿。文件和成员使用单一主内容，保留禁用的折叠按钮槽位，导航按钮位置稳定。
`shell/WorkspaceShell.tsx` 管理中栏调宽与响应式限制，`duallane-workspace-list-width` 只存本机宽度，
不包含账号、消息或草稿，也不进入服务端配置。拖动过程不逐帧写存储，取消恢复原值。
中栏会话按钮直接绑定共用对象动作控制器，不常驻三点按钮；其余对象入口按对象操作规范保留。
中栏会话／话题选中底色来自主题派生变量 `object-list-selected`，与背景和未选中悬停分离。
桌面详情宽 360px，标题及正文分别组织，正文独立滚动；手机详情是整页。未选对象时不显示先前会话的详情。
手机根页面显示同一份底部导航，进入会话或详情后优先显示内容和返回入口。
个人设置拥有固定分类轨及独立滚动内容，手机按目录、类别、子页逐级进入；个人首页提供退出登录。
`/workspace/account/appearance` 是可刷新、可分享返回位置的正式路由。
`/workspace/account/emotes` 也是普通设置分类；管理弹窗只由显式操作打开。
弹窗状态独立于路由，关闭时保留设置页或原会话，导航与退出清理该临时状态。

用户菜单只保留配额摘要、重新同步、返回入口和退出登录，常用页面通过主导航到达，避免菜单重复目录。

浏览器历史带 `duallaneIndex`。需要保护时先恢复当前历史位置，再询问；取消不销毁前进记录。
`useNavigationGuard` 在副作用前保留完整用户意图，保存失败不执行后续导航。
已经明确选择“不保存并关闭”的动作使用 `runConfirmed`，不重复询问，也不在确认前清除记录。

Workspace 会话草稿和待添加附件仍由领域控制器按会话管理，换导航和外观不会把它们写入主题存储。
退出、返回通道选择和应用内刷新会说明未发送内容；关闭浏览器时只能请求平台允许的离开提示，不能保证一定弹出。
这不是持久草稿或跨设备同步功能，不能承诺刷新后恢复未发送内容。

## 两条通道的具体流程

私密会话创建后立即进入聊天壳，等待邀请是正文中的一个状态，不再要求二次点击才建立连接。
创建操作有请求互斥和过期会话检查，口令放在可展开的安全设置中，固定两人改为说明。
结束或返回先确认，再断开连接并进入本机记录选择；直接导出不依赖浏览器存储成功。
P2P 消息、草稿、密钥和文件仍遵循原内存及用户明确保存的边界，不进入 Workspace 缓存。

共享消息的右键、长按、更多和键盘入口使用同一菜单组件。动作由当前消息状态和现有能力生成；
本地未完成消息不提供服务端常驻或撤回。正文、链接和可编辑内容保留原生选择与菜单。
对象失效会关闭菜单并恢复到消息列表；隐藏操作恢复编辑器焦点。

P2P 的 ChatPanel 也使用共享对象菜单，但按房间独立作用域，只提供既有的复制、失败重试和文件接收/拒绝/本机保存。菜单不增加网络接口，不借用 Workspace 的回复、常驻或撤回能力。

文件、成员、会话与话题使用同一个 `ui/patterns/useObjectActionScope` 控制器，每列表一个实例。
动作由现有对象能力生成；文件详情与快捷下载共享权限、状态和配额判断。
会话详情中的成员一行一个可见“更多”，与右键、长按共用动作；受限对象不渲染无权执行的管理动作。
危险命令使用 `ConfirmationProvider`。账号会话失效会撤销待确认意图，即使点击确认与失效发生在同一任务中也不能执行旧操作。

群邀请使用独立 `features/members/MemberPickerDialog` 搜索实际候选并多选。选择器只管理选择与交互，App 按既有单成员接口串行添加；成功成员移出待提交集合，部分失败只重试未成功项。
每次请求及响应均校验账号、群和权限作用域，失效时中止后续请求。它不是原子批次，取消请求不代表已成功添加的成员被回滚。

话题创建使用独立 JSON 字段与幂等键，不拼接快捷语法。各话题在本次登录期间分别保留草稿、回复、同步选择、失败消息和阅读位置；退出与刷新检查所有话题。
创建请求成功可以结束尚未执行的返回确认，优先打开明确创建出的对象；资料保存中的旧意图继续由其确认框持有。
话题标题、归属和状态与工具栏分层；状态标记按内容宽度排列，参与、提醒和管理操作分别组织，不以伸满横栏的状态块代替标题层级。

资料使用显式 PATCH 保存。偏好保留真实自动保存，并就地显示失败、已确认值与重试。
资料页把头像、昵称编辑、保存／取消区及只读登录身份分开；保存操作不再充当一个字段。通知子页将渠道、频率、地址和验证命令按依赖关系组织，同类帮助与反馈对齐。
提交中的资料请求不能被“放弃”伪装成已经撤销；退出账号后的迟到响应不能回写新账号。
SMTP 仍是空间能力，不因放在同一个设置目录而变成个人设置或绕过空间授权。

Bot 私聊上下文授权通过原 `context-grants` API 提交；群聊使用原 `group-policies`。
私聊缺少读取接口时展示“尚未读取当前授权”，不伪造既有值。授权不会扩大 Token scope 或自动批准入群。
Bot 内容按资料、连接、授权、凭据四个同级章节呈现；Echo 需求和公开征集使用同级 Tab，切换保留草稿并使用单一正文滚动区域。
空间可见范围的 GET、PUT 结果同时校验查看者、账号及请求代次；保存中锁定查看者，避免把上一对象的列表提交给下一对象。
空间角色和可见范围页面使用搜索与扁平成员行；布局调整不改变成员可见性、角色分配或系统身份限制。

## 后端及发布边界

无新增数据库迁移，Go 仍是唯一在线服务。话题 API 在现有路径兼容增加完整消息字段与 around 查询；topic-scoped transaction adapter 调用普通消息服务，统一内容与关联写入，同时保留话题的成员、状态、保留、通知和同步规则。话题附件先进入 private_staging，关联消息后按当前话题访问权限读取，不提前向整个群公开。
私密通道不持久化服务器内容，`#k=` 不进入请求、日志或遥测；Workspace 的授权、配额、
保留、审计和幂等继续由原服务负责。测试环境使用单独的合成数据和隔离容器。

发布时使用同一套新设计语言；主题是参数变化。未提交或未合并的代码不等于线上已切换。
读屏、真实手机软键盘与安全区、非 Chromium 浏览器的人工验收按覆盖账本单独记录。
