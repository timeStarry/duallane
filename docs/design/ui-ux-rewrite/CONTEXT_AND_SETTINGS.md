# 对象操作与个人设置

状态：本次重构最终的对象动作与设置规范。实际模块见 [架构](ARCHITECTURE.md)，验证结果和未覆盖范围见
[PR 验证记录](PR_VERIFICATION.md)；规范确定不代表全部设备验收完成或已经生产发布。
本文补充 [方案入口](README.md)、[体验契约](EXPERIENCE.md)、[设计系统](DESIGN_SYSTEM.md)
和[覆盖账本](COVERAGE.md)。权限、API、数据、配额、审计及两通道的隐私边界不变。

## 1. 适用范围与唯一规则

- 同一对象通过右键、长按、可见“更多”和键盘打开同一组适用动作；入口不会改变操作后果。
- 菜单是发现动作的辅助方式，触控和键盘用户始终有可见、可聚焦的入口。
- 个人设置是独立完整主视图；页面层级承载持续编辑，弹窗只处理短确认或明确的临时任务。
- 普通偏好反馈稳定，资料编辑可明确保存；危险与授权命令保持显式，不由自动保存触发。

当前实现通过[共用会话组件](../../../apps/web/src/features/conversation/WorkspaceChatPanel.tsx)、
[对象操作基础组件](../../../apps/web/src/ui/primitives/index.ts)、
[设置布局](../../../apps/web/src/features/settings/SettingsLayout.tsx)和
[个人设置](../../../apps/web/src/features/settings/WorkspaceAccountSettings.tsx)承接这些规则。
群聊、私聊与话题共用完整消息和编辑器行为；P2P 只复用适用于其信任通道的动作与呈现。
不得将旧基线、HTML Demo 或阶段记录中的菜单子集、自动弹窗、延迟保存昵称等行为作为另一套规范。
视觉尺度、材质、分段单选和导航 Tab 的区别统一按 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)，本文不另设尺寸。

## 2. 一份动作定义，适配多种入口

动作注册表描述稳定动作 ID、目标对象、文字／图标、排序、分组、可见／可用条件、
禁用原因、确认要求与执行处理。各入口只选择呈现位置，不复制业务处理逻辑。
动作依据对象类型、当前权限、消息／任务状态和通道能力计算；打开与执行时都校验当前对象。
服务端继续逐次授权，菜单中的权限判断不替代它。

| 对象 | 可承接的现有动作与目标组织 | 边界 |
| --- | --- | --- |
| Workspace 群聊／私聊／话题消息 | 共用回复、复制消息、个人隐藏／恢复、表情回复、适用的表情收藏和失败重试；群和话题按能力常驻／取消常驻，自己可撤回的消息显示撤回 | 每种动作按消息和页面状态筛选；系统／撤回／待发送消息不伪装为可回复或可撤回；个人隐藏不等于共享删除 |
| 群内常驻消息 | 常驻和取消常驻来自同一动作定义 | 不是会话置顶；保留当前每人每群上限及 `canUnpin`，不能常驻任意他人消息 |
| 话题专有补充 | 在完整共用消息动作上增加“同步到群聊／取消同步” | 按加入关系、话题状态、`allowSyncToGroup` 和投影权限提供；不默认同步，不以共用菜单绕过话题访问控制 |
| 文件／传输任务 | 可用时下载、打开来源会话、受权移除；失败任务的重试／移除本地记录 | 按真实能力区分服务器文件与本地任务；移除文件不是撤回消息，下载仍受权限与配额控制 |
| 会话／成员 | 汇集现有详情入口及对象允许的私聊、群管理、提醒等操作 | 不新增未经实现的置顶／屏蔽／批量删除；具体项与覆盖账本、对象 capability 对齐 |
| P2P 消息／文件 | 仅注册该通道已有的复制正文、失败重试、文件接受／拒绝和本机保存等适用动作；文字仍可原生选择复制 | 不凭通用面板参数开放未启用的回复／提及；不显示云端收藏、共享撤回或空间权限动作 |

“复制消息”复制现有序列化得到的可读内容，可能包含提及标签、链接、表情 token、附件名等；
不标为“完整无损原文”，不新增结构化 JSON 或图片二进制复制承诺。
“回复”建立明确的目标消息关系，不是复制或转发；原消息不可见时不虚构其正文，仍保留回复边界。
“撤回消息”按共享消息协议处理正文及投影，不能改名为含糊的“删除”；文件移除、本地任务移除和个人隐藏
分别描述自己的后果。话题常驻内容仅在有权读取该话题的范围内投影，不能借父群常驻列表公开给未加入者。
无权限项目通常不出现；仅对用户已经有权知道的暂时不可用动作显示禁用原因。
资源在菜单打开后被删除或撤权时，执行安全失败并更新菜单，不泄露隐藏对象。

会话详情中的成员以一人一行呈现，每行只有一个可见“更多”，常用和危险动作统一进入该对象菜单。
消息的透明行内工具栏也从同一动作集合取项，不增加另一组命令或有色悬浮面板；悬停只影响桌面呈现，
触控和键盘仍能找到“更多”。消息分组不改变单条消息的动作目标，菜单打开期间追加或加载历史不能错绑对象。

## 3. 桌面右键与键盘

在可操作对象的空白／操作区域右键，菜单靠近指针出现；点击“更多”则锚定该按钮，
Shift+F10 或平台菜单键锚定当前可操作对象。文本、链接、输入框、可编辑内容和原生媒体
控件保留浏览器菜单与选择行为；不能全局拦截 `contextmenu` 或关闭文本选择。

- 使用 Portal 避免被消息列表裁切；菜单与目标通过稳定 ID 关联，不依赖挂载层级判断对象。
- 以当前可视视口计算位置，右侧／底部不足时翻转或收拢；窗口缩放、软键盘和浏览器工具栏
  改变可用区域时仍可操作。超高菜单内部滚动，不把危险动作挤到屏外。
- 打开后聚焦首个可用项；上下、Home／End 移动，Enter／Space 执行，Escape 关闭。
  Tab 退出菜单并按正常焦点顺序继续，不能把用户困在非模态菜单中。
- Escape／取消返回触发控件；外部点击关闭后，焦点留在用户点击的有效控件，否则回到触发源。
  触发对象已移除时回到最近有效对象或主内容，不聚焦已卸载节点。
- 外部关闭依据菜单 Portal 与触发源的实际事件路径判断；点菜单内容不能误触外部关闭。
  同一时刻只有一个对象菜单；切换对象先更新目标再显示，不保留旧目标的动作闭包。
- 用户通过滚轮、触摸、滚动键或滚动条滚动对象所在区域时关闭桌面菜单。历史前插、浏览器锚定和实时更新
  导致的程序性滚动／分组重排不视为新的滚动意图；对象仍有效时保留菜单和焦点，按钮菜单跟随锚点更新，
  右键菜单保留打开点位；对象移除、撤权或切换仍须关闭。不能以增大位移容差或在测试里重复打开菜单
  代替正确区分。

仅打开菜单不执行任何动作。选择危险操作先关闭菜单，再打开独立确认，明确对象、后果与
“取消／确认”标签；确认完成或取消后的焦点回到合理位置，不叠加多个菜单和确认层。

## 4. 手机长按与底部动作面板

长按只在消息空白／专用操作区域启动候选识别；可见“更多”与长按使用同一动作定义。
正文、链接、输入框和可编辑内容继续支持原生选择、复制、链接预览与编辑菜单。
不得全局使用 `user-select: none`、`touch-action: none` 或 `preventDefault()` 换取长按。

| 手势状态 | 处理规则 |
| --- | --- |
| 单指按下适用区域 | 记录对象、指针、起点；约 450ms 后才可打开，按下本身不执行动作 |
| 持续移动超过 10 CSS px | 取消本次长按候选；阈值按与起点的距离判断，不能重置起点规避取消 |
| 页面／列表开始滚动、出现第二指针 | 取消计时与候选，保留原生滚动／缩放，不打开菜单 |
| `pointercancel`、离开页面、对象卸载、提前松开 | 清除计时与引用；后续回调不得打开旧对象菜单 |
| 达到时间且仍满足条件 | 打开一次底部动作面板；仅消费这次手势关联的重复 `contextmenu`／合成点击 |
| 快速点“更多” | 立即打开；不要求长按，也不执行默认业务动作 |

面板显示简短对象摘要，避免用户忘记操作目标。常用动作在前，低频动作随后，危险动作
分组并保持明确确认。命中区按设计系统执行；底部适配安全区域，内容超高时内部滚动，
关闭按钮固定可达。不要在摘要中显示令牌、内部路径、邀请秘密或无权查看的消息。

面板按模态 dialog／sheet 管理焦点与背景交互，包含可访问名称；Escape、关闭按钮和安全的
遮罩点击能关闭，并恢复逻辑焦点。打开／关闭不能滚动背景消息列表或重建编辑器。
减弱动态时直接呈现最终位置；换主题或旋转设备不重复开面板，不切换动作目标。

## 5. 个人设置布局与层级

桌面使用完整设置主视图：左侧稳定类别导航，右侧显示一个类别或子页。
页面标题说明当前归属，内容按有标题的设置组组织；不把每个类别装入新的模态窗口。
平板在足够宽时沿用双栏，窄窗口按移动层级处理，断点遵循设计系统。
分类导航与内容分别滚动，内容宽度有上限；资料头像、编辑字段、保存区和只读身份分开。
保存／取消区是表单操作，不画成带标签的字段。通知子页依次组织渠道开关、频率、接收地址及验证，
同类行的标签、帮助、状态与控件对齐，窄屏按同一顺序堆叠。

七个类别的顺序与名称固定，桌面和手机共用同一目录。手机从设置首页进入类别，再进入必要子页：

```text
个人设置
├─ 个人资料 → 昵称／头像等可编辑资料；GitHub 身份只读
├─ 外观 → 主题、浅深模式、密度、动态、透明材质
├─ 聊天 → 显示与发送偏好；仅列现有可用能力
├─ 通知 → 渠道总览 → 邮件 / 移动推送（ntfy）
├─ 隐私 → 成员可发现性等既有偏好
├─ 表情 → 正常设置页面 → 显式打开“管理我的表情”工具
└─ Bot 与连接 → 自有 Bot → 资料／连接／授权／凭据四个同级章节

独立账号操作区：退出登录（不构成第八个类别）
```

类别与邮件／ntfy 子页对应有效路由；Bot 章节在 Bot 页面内切换，不把每个章节宣称为独立路由。
有效旧深链接与返回目标通过明确路由映射承接。Bot setup 批准与历史上下文授权是不同命令，不能合并。
“Bot 与连接”只收纳当前账号有权管理的集成；P2P 连接详情仍在私密直连上下文，空间
服务连接和空间管理也不混入个人设置。退出登录位于独立账号操作区，不与返回入口混淆。
本轮不因该目录增加账号注销、浏览器原生推送或跨设备设置同步。

### 5.1 类别、子页与工具层

返回顺序确定为：邮件／ntfy→通知→个人设置，其他类别→个人设置；个人设置根级返回聊天视图。
直接深链接使用相同父级，不依赖不存在的浏览器上一页，不跳到未知外站。类别内容按当前页面会话保存
其滚动位置；返回目录聚焦原类别入口，进入类别聚焦页面标题。桌面类别切换、手机返回和浏览器历史变化
必须经过同一未提交修改检查；取消时页面与 URL 都留在原上下文。

`/workspace/account/emotes` 是正常可阅读的设置分类页，进入或刷新该路由不自动打开弹窗，也不为了
呈现表情工具退回其他路由。用户显式点击“管理我的表情”才打开上传、排序、收藏、合集、分享与订阅工具；
关闭工具留在表情分类并恢复入口焦点。聊天中的表情选择器仍服务于当前编辑器，其显式管理入口复用同一
工具，关闭后返回会话的合理焦点。分类页面、编辑器选择器和临时管理工具各有明确责任，不能相互冒充。

群、空间和个人设置内页都采用“常用信息／偏好→必要子页或同级章节→低频管理命令”的层级。
主页面不堆叠所有令牌、授权、轮换和删除表单；也不将每个设置变成弹窗。明确确认、短任务选择器和
显式打开的表情管理工具可以使用临时层，关闭后必须留在原任务的路由与作用域。

Bot 的资料、连接、授权、凭据是同级章节，使用导航 Tab；切换保留仍然有效的资料、令牌描述和授权草稿。
单会话上下文授权明确区分 `allowTrigger`、`allowContext` 与 `maxMessages`，显式保存或关闭授权；
仅展示服务返回的可管理对象，未获授权状态保持只读。Token scope 仍独立限制能力，不能称其为完整历史授权。
Echo 的需求／公开征集为同级入口；其筛选、流程动作与草稿状态遵循同一内页层级，不因低频而省略。

### 5.2 外观与固定单选

外观页用实际主题 Token 绘制包含导航、消息和编辑器的微型产品预览，只显示标题、预览和选中标记，
不加每张卡的小字说明。主题沿单行横向浏览，条带内部可以滚动，页面不能因此横向溢出。
触摸滑动、鼠标超过拖动阈值后拖动、左右浏览按钮只改变浏览位置；点击或键盘确认才保存选择。
拖出条带松手不误选，随后点击和 Enter 仍正常；键盘移动到离屏选项时自动使它可见。

显示模式保留“跟随系统／浅色／深色”三种值，以带图标的分段单选呈现。主题家族、明暗、密度、动态和
透明材质互相独立，不能因为切换主题重置其他偏好。外观即时应用并只持久化到这台设备；存储不可用时
明确提示仅本次页面生效，并允许重试，不声称已同步账号或其他设备。

固定且不超过四项、文案简短的互斥设置、筛选和展示模式统一使用共用分段单选；长文案、需要解释的选项、
动态或更多选项使用 Select。空间不足时由共用组件回退 Select，保留值、标签、键盘与焦点语义，不能硬挤、
截断或换成两行分段选项。分段单选具有共享圆角底座和内嵌选中面，不使用导航 Tab 的指示条。
文件／相册“列表／卡片”遵循相同规则，图标加短标签只改变展示方式，不切换数据范围。具体视觉见设计系统。

### 5.3 群邀请的短任务边界

群邀请是允许使用独立对话框的短任务，由 `features/members/MemberPickerDialog` 管理候选搜索与多选。
确认后按原单成员接口串行提交；成功项从待选集合移除，失败项保留重试，作用域失效时中止后续提交。
这是非原子操作，已成功添加不会因其他项失败而回滚。选择器不把角色名称当作授权依据，
不展示隐藏成员；服务器仍逐次校验群管理和对象准入能力。

## 6. 修改、保存与离开

| 设置类型 | 提交方式 | 失败与恢复 |
| --- | --- | --- |
| 普通布尔／枚举偏好 | 用户明确改变后沿用自动保存，显示正在保存／已保存 | 就地显示失败和重试，并说明当前是预览值还是已确认值；不静默假示成功 |
| 资料编辑 | 显式“保存／取消”；仅在有有效改动时可保存 | 校验就地显示，失败保留输入；取消只还原未提交草稿，不撤销此前已保存数据 |
| 令牌、授权、轮换、连接测试、删除等 | 明确命令，危险动作独立确认 | 不由失焦、导航或开关连锁自动执行；单次秘密只在许可位置显示 |
| 外观选择 | 即时应用并保存到当前设备；不调用账号偏好接口 | 不重建会话、草稿、菜单或阅读状态；本机保存失败不等同应用失败，提示仅本次页面生效 |

只在存在用户尚未提交的有效改动时询问是否离开；无改动、只读页、已确认保存不反复询问。
选择“保存并离开”后等待真实成功；失败留在当前页保留输入。选择放弃只丢弃本次草稿。
保存进行中不得通过放弃触发第二次保存或假装撤销已经提交的 PATCH；离开决策必须等待当前提交结果并
以最新状态判断，取消确认不清空字段。全局退出／重新同步还须单独说明当前账号下未发送的会话和话题草稿
及待发送附件；保存个人资料不等于保存聊天草稿，不能用“保存并离开”含糊地承诺两者都已保存。
自动保存请求进行中不伪装成未提交表单：请求继续按账号／目标作用域跟踪，失败结果可找回。
主题演示的内存预览不会凭空形成一个需要保存确认的真实账号表单。

连续快速修改按字段、账号和目标串行或合并提交，旧请求结果不能覆盖用户的新选择；
只过滤旧响应还不够，最终服务端值也必须与最新已确认选择一致。离开、换号、撤权后
返回的响应不得污染新账号。多字段资料使用既有接口时不承诺不存在的原子保存：部分失败
逐项说明，保留尚未成功的输入，不能统一显示“已保存”。
