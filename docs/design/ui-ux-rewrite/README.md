# DualLane UI/UX 最终规范：清晰双轨

状态：本次重构及后续补充的正式规范；分支已实现并进入 PR 验证。规范已确定，完整设备与辅助技术的发布验收尚未完成，尚未发布。

设计名称：清晰双轨（沿用 V2 方向并包含全部后续修订）；重构前代码基线：`ef51873`（0.18.0）；规范整理日期：2026-09-11。

## 1. 决策与交付边界

本方案将视觉语言、信息架构、交互流程、状态反馈和多端适配作为同一版本交付。
用户已确认优先完整统一的体验，支持一次性重写全部页面；工程分工不能成为保留旧页面、旧控件或两套导航的理由。
默认主题延续铜橙／青蓝，但组件从第一天支持更多主题及每个主题的浅深模式。

当前分支已接入正式主题、组件库、组件工作台、统一页面布局、对象操作和新的设置及话题流程。
首轮统一样式之后，本轮继续调整真实页面的导航、滚动、详情、选择与设置层级；仅替换配色和圆角不能视为完成页面重构。
实际结构见 [前端架构](ARCHITECTURE.md)，最终提交检查见 [PR 验证记录](PR_VERIFICATION.md)。[页面精修](PAGE_REFINEMENT.md)、[会话一致性记录](CONVERSATION_PARITY.md) 和 [首轮验证](PRODUCTION_VERIFICATION.md) 保留阶段证据，不再承担当前规则定义。原型是历史设计样例，不连接产品 API，也不是生产代码的复制来源。
文档里的要求、分支中的实现、通过验证的场景与生产发布是四种不同状态。

Demo 是设计方向与局部交互样例，不是正式页面的施工模板。正式重构必须结合真实任务、
内容、权限、异步状态及设备约束继续优化，并交付实际组件库、直接使用正式组件的工作台、
与代码同步的架构文档及设计调整证据。执行要求见 [重构交付与持续设计规则](DELIVERY.md)。

## 2. 可观察的版本结果

1. 从入口、聊天、话题、文件到个人和空间设置，所有页面使用同一套组件、排版、状态和交互规则。
2. 共享空间以“聊天／话题／文件／成员／个人”为日常导航；owner/admin 另有“空间”，普通成员不显示管理入口。旧空间深链接仍按服务端能力安全呈现。
3. 私密直连创建后在会话内邀请、等待与交谈；离开和结束遵循一致的未保存内容与传输处理规则。
4. 话题通过表单自然创建；选择已有话题先进入目标讨论；页面位置、草稿归属与发送目标一致。
5. 查看详情、切换页面或改变主题后，用户能继续原任务；草稿、选中对象和阅读位置按正确作用域保留。
6. 聊天和话题可折叠中栏；文件和成员使用单一主列表。桌面详情使用独立滚动的 360px 侧栏，手机详情为整页，未选对象时不残留旧详情。
7. 主题使用实际色值的微型产品预览卡；主题、浅深模式、密度、动效、透明效果相互独立。新增主题不会产生新组件副本。

以上是实现与验收契约，不能据此推断每个角色、浏览器和失败分支均已通过。具体证据及开放项以覆盖账本和本轮记录为准。

## 3. 权威性与现有文档关系

本目录是当前版本及后续 UI/UX 修改的唯一体验规格入口。规范中的“必须／不得”是验收约束，“可”是明确允许的变体；“待验收”仅表示证据未完成，不表示可以改用旧规范。

| 要修改的内容 | 唯一规范归属 | 配套事实或证据 |
| --- | --- | --- |
| 颜色、尺寸、材质、动效、主题、控件选型、消息视觉 | [设计系统](DESIGN_SYSTEM.md) | 正式 Token 和共享组件 CSS；原型数值不覆盖它们 |
| 导航、中栏／详情、聊天／话题、文件与全局流程 | [体验与流程](EXPERIENCE.md) | [实际架构](ARCHITECTURE.md)、领域协议 |
| 右键／长按／更多／键盘、设置目录、保存与返回 | [对象操作与个人设置](CONTEXT_AND_SETTINGS.md) | 正式组件 API 和设置服务适配 |
| 必须承接的页面、浮层及后续补充项 | [覆盖账本](COVERAGE.md) | 逐项链接实现和验收证据，不另行定义视觉数值 |
| 完成条件与设备／状态范围 | [验收矩阵](ACCEPTANCE.md)、[交付规则](DELIVERY.md) | [PR 验证记录](PR_VERIFICATION.md) 区分通过、未运行与发布前工作 |

后续修改先更新归属文档中的原规则，再同步实现、消费者与回归；不得仅在阶段记录末尾追加一条相反说明。
发现代码与规范不一致时按缺陷处理，不能让页面局部实现成为第二套规范。已经确认的设计变更须同步本表归属及覆盖账本。
历史原型、阶段截图、旧视觉文档和旧测试选择器均不能覆盖当前规范；它们只解释演变或提供复现证据。

当前版本的导航归属、组件尺寸、材质、主题与流程按以上规范实施。
旧视觉文档中的“小于等于 8px 圆角”“文件放工具菜单”“仅聊天／话题／成员主导航”等不再限制目标版本。
旧文档中的视觉、导航及页面布局段落统一作为历史参考；未被替代的权限、数据和协议条款继续有效。
入口提示链接到这里，不能再从旧稿选择与当前规范不同的 UI 方案。

以下契约持续优先，不能由视觉或流程设计改写：

- [AGENTS.md](../../../AGENTS.md) 与 [系统／通道设计](../../../DESIGN.md)。

## 4. 本版必须做与另外定义的能力

| 范围 | 决策 |
| --- | --- |
| 全页面重写、共用组件、多端布局、主题基础 | 本版必须完整覆盖 |
| 上述导航、P2P 连续流程、话题创建与进入、状态延续 | 本版体验目标；每项需真实链路验收 |
| 当前已有邮件／推送、Bot／Echo、表情、权限及管理入口 | 保留能力并统一重写，不能因低频而遗漏 |
| 会话／成员／文件查找、消息定位等已有能力 | 保留准确范围与权限；输入提示必须与实际检索一致 |
| 话题完整消息与附件 | 本版已包含，复用常规消息管线与组件；权限、归属及兼容以话题领域契约为准 |
| 全文历史检索、跨设备草稿同步 | 另外定义的候选能力；不把原型或旧路线图当成已实现协议 |
| 原生 iOS／Android 客户端、外部任意主题导入 | 提前建立可复用语义与偏好结构；不在本次文档交付中宣称原生实现或开放导入 |

全量覆盖以最新可用产品能力为准，不能把早期 MVP 文档的非目标用作删去后续已实现能力的理由。

## 5. 隐私、数据与兼容要求

| 项目 | 不变约束 |
| --- | --- |
| 私密直连 | 消息和文件默认仅留在当前浏览器会话内；服务端不保存正文；不经过 Workspace 存储 |
| 邀请 | `#k=` 只在浏览器内使用，不进入 API、日志、埋点或服务器渲染 |
| 本地保存 | 用户明确操作后才保存／导出；说明本机明文的可访问范围，不承诺浏览器关闭时必定保存 |
| 共享空间 | 服务端权限、配额、保留、审计、幂等与实时可见性继续成立；精简 UI 不减弱校验 |
| 主题偏好 | 只保存外观选择；不能夹带聊天内容或跨通道草稿；原型没有自动持久化 |
| 兼容 | 保留有效深链接、消息协议、已有存档和数据格式；必要转换明确版本、回退与回归场景 |

## 6. 本地评审与检查

从仓库根目录运行文档检查；它验证规范、领域入口及组件 README 中的本地文件、引用式链接和 Markdown 标题锚点：

```bash
node docs/design/ui-ux-rewrite/verify-docs.mjs
git diff --check
```

正式组件工作台直接使用产品组件。在正常开发服务中打开 `/__design`；只评审组件时，可从仓库根目录启动前端：

```bash
corepack pnpm --dir apps/web exec vite --host 127.0.0.1 --port 5186
```

打开 `http://127.0.0.1:5186/__design`，可以实际操作主题、开关、选择器、滑块、Tab 和对象菜单。这个入口仅存在于开发构建；评审正式业务页面仍需要对应 Go 服务。
组件约定与检查入口见 [组件库说明](../../../apps/web/src/ui/primitives/README.md)，正式主题的唯一数据源见 [主题基础](../../../apps/web/src/ui/theme/README.md)。

以下命令检查保留的 HTML 原型。依赖使用仓库现有 Playwright，无需产品服务或数据库：

```bash
node docs/design/ui-ux-rewrite/prototype/verify.mjs
node docs/design/ui-ux-rewrite/prototype/sync-interaction-lab.mjs --check
node docs/design/ui-ux-rewrite/prototype/verify-interactions.mjs
node docs/design/ui-ux-rewrite/prototype/verify-selection.mjs
node docs/design/ui-ux-rewrite/prototype/verify-controls.mjs
git diff --check
```

原型可以直接打开 `prototype/index.html`。需要浏览器 HTTP 预览时，从仓库根目录执行：

```bash
python -m http.server 5179 --bind 127.0.0.1 --directory docs/design/ui-ux-rewrite
```

打开 `http://127.0.0.1:5179/prototype/index.html`；若端口已占用，选择另一个空闲端口。
此命令仅提供静态文件，结束评审后用 Ctrl+C 关闭。

原型是视觉与交互基线，尚未实现本方案全部新流程：例如示例导航与正式“话题”路径不能代替 [体验规格](EXPERIENCE.md)。
报告新增“右键与长按”和“个人设置”两个可操作区域，包含对象菜单／底部面板、七类设置目录、通知与 Bot 子页、资料保存和失败演示。
消息和保存结果均为本页模拟；表情库等复杂工具这里只展示归属，完整能力仍按覆盖账本实施。
这两个区域的源码为 `prototype/interaction-lab.html`、`.css`、`.js`；编辑后运行
`node docs/design/ui-ux-rewrite/prototype/sync-interaction-lab.mjs`，同步到可独立打开的 `index.html`。
组件实验室的 `#selection-patterns` 提供侧边／底部两种可操作 Tab；圆角底面与等宽细条的规则
同时用于报告目录、个人设置、会话列表和横向切换。对应源码为 `selection.css`、
`selection-lab.html`，同样通过上述同步脚本内嵌；键盘行为位于 `interaction-lab.js`。
`#control-details` 补充下拉、滚动和滑块样例；源码 `controls.css`、`controls-lab.html` 也由同一脚本同步。
历史原型的可定制下拉在支持的浏览器里增强样式，其他浏览器保留系统选择器；正式应用已使用共享 Select，不能以这个原型回退策略作为正式控件标准。
截图和原型的成功不能替代正式应用的认证、权限、传输、重连和持久化验收。
本次实际检查结果见 [验证记录](VERIFICATION.md)。
