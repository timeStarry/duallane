# 全量重写实施与切换

状态：当前分支已进入正式应用集成与回归。本文保留目标约束；已实现边界以 [实际架构](ARCHITECTURE.md) 为准。
范围与优先级由 [总方案](README.md) 定义，功能清单见 [覆盖账本](COVERAGE.md)。
组件库、工作台、实际架构文档和正式设计迭代按 [交付契约](DELIVERY.md) 同步完成；
不得把 Demo 的页面布局、样例状态或全局脚本作为正式实现模板。

## 1. 技术决策

沿用 React、TypeScript、Vite、Lexical、Lucide 和当前 Go 后端。
重写解决当前大页面同时承担路由、状态、会话、设置和样式的问题，不以更换框架作为前提。
不增加第二套 UI 框架、全局状态库或在线 Node 服务。新增依赖按现有架构规则给出必要性和验证。

在 `apps/web/src` 内按以下职责组织模块；实际文件与尚未拆分的控制器见 [实际架构](ARCHITECTURE.md)，不要求机械创建每一层目录：

| 归属 | 职责 | 不应承担 |
| --- | --- | --- |
| `ui/theme` | Token、主题注册、偏好解析、CSS／平台值映射、合法性与对比度检查 | 会话数据、权限和网络请求 |
| `ui/primitives` | 按钮、输入、开关、Select／Combobox、滚动区域、Slider、菜单、对话框、头像和反馈基础组件 | 某个页面专属业务规则 |
| `ui/patterns` | 设置行、消息布局、编辑器容器、附件和详情布局 | 改写领域协议或复制后端权限 |
| `shell` | 通道、全局导航、列表／内容／详情布局、窗口适配 | 消息传输、上传实现或主题分支页面 |
| 领域页面模块 | P2P、Workspace 聊天／话题／文件／成员／设置／Bot 页面组合 | 自定义全局按钮、间距和颜色体系 |
| 现有 API／实时／领域适配层 | 授权数据、发送、幂等、订阅、传输与错误映射 | 控制组件内部焦点或写入页面样式 |

App 仅保留必要的组合和生命周期协调。既有经过验证的消息、API、加密、权限和文件行为在明确边界下复用或搬迁。
领域差异通过能力与适配表达；不把 P2P 和 Workspace 草稿、传输或存储放到同一个默认持久化缓存中。

## 2. 状态所有权

| 状态 | 所有者与作用域 | 页面切换／退出约束 |
| --- | --- | --- |
| 当前对象和路径 | 路由与导航协调层 | 深链接和浏览器前进／后退有效；未授权对象安全失败 |
| 正文与资源实体 | 现有 API／实时数据层，服务端权威 | 取消过期请求，事件去重，不因换主题重新拉全量数据 |
| Workspace 编辑草稿 | 按账号、空间、会话类型和资源 ID 隔离 | 切换保留；退出账号／失去权限清理敏感内容；跨设备同步另行定义 |
| P2P 消息与草稿 | 当前私密会话内存 | 默认不自动落盘；明确保存和结束后清理 |
| 阅读锚点和列表筛选 | 资源视图状态 | 返回和窗口变化恢复；删除／保留清理后使用安全邻近锚点 |
| 传输任务 | 领域传输协调层 | 路由切换不误取消；重试／恢复能力按现有协议提供，不虚构断点续传 |
| 表单修改与异步保存 | 具体设置领域 | 保存失败保留输入；敏感命令明确提交；旧响应不覆盖新选择 |
| 外观偏好 | 版本化个人／设备偏好适配层 | 与上述数据独立；即使读取失败也有完整内置主题 |

共享编辑器必须覆盖 IME、提及、回复、粘贴、附件、光标、焦点、尺寸和 Strict Mode 生命周期。
话题与群聊的发送目标属于资源路由；旧入口切换后不能把未发送群聊草稿静默搬进话题。

## 3. 工作顺序与出口

这些步骤用于实现和评审组织，不代表分批向用户开放两套界面。

| 步骤 | 工作产物 | 进入下一步的条件 |
| --- | --- | --- |
| A：确认约束与覆盖基线 | 更新覆盖账本、导航与路径、六条任务流程、状态和能力边界 | 每个现有入口有目标归属；新功能与重排已有能力区分清楚；页面细节在真实验证中继续完善 |
| B：设计基础 | 正式主题与偏好、组件库、直接导入正式组件的工作台、壳层和实际架构边界 | 五套主题明暗、开关几何、控件选型、键盘和关键状态通过组件验证；使用接口与状态规则有文档 |
| C：核心纵向任务 | 两通道入口、P2P 邀请到结束、Workspace 聊天和话题 | 用真实服务与虚构测试数据完成核心任务，保留权限与幂等 |
| D：完整页面覆盖 | 文件、成员、设置、通知、表情、Bot／Echo 和所有浮层 | 覆盖账本没有遗漏或旧页面；角色与能力不会回退 |
| E：统一验收与清理 | 场景验证、设计调整与视觉证据、架构文档同步、性能基线比较、旧依赖清理、发布说明和兼容记录 | [验收矩阵](ACCEPTANCE.md)、交付契约和仓库规定的门槛通过 |

每项更新账本状态为“待实施／实施中／待验证／已验证”，附对应变更、测试命令和证据。
当前页面已接入新主题和布局，重点流程已改造；自动化、视觉检查和仍需人工验证的范围分别记录在验证文档中。不能用原型可打开或全局样式覆盖代替功能验收。

## 4. 兼容与明确的变化

| 内容 | 实施要求 |
| --- | --- |
| 既有路由与深链接 | 建立旧地址到新页面的明确映射；有授权后回到意图目标；不存在和无权访问不泄漏资源存在性 |
| 话题创建快捷语法 | 保留既有解析与幂等语义；表单优先复用当前领域能力，不能简单拼接未转义文本导致标题／正文被误解析 |
| 旧明暗主题偏好 | `ui/theme/preferences.ts` 将旧模式映射到 `original + mode`；无效值安全回退，迁移可重复且不修改消息存档 |
| 消息、附件、卡片 | 保持协议版本、client ID、引用、授权下载和去重行为；不通过 UI 重写重存历史数据 |
| 本地 P2P 存档 | 旧格式可读；升级先验证再写，读失败不删除原数据；只在用户明确操作时改变保存状态 |
| 外观保存 | 当前使用版本化设备偏好；账号同步不在本版范围，需另补 API／冲突处理契约 |
| 话题消息与附件 | 本版复用普通完整消息模型、发送服务与渲染；兼容扩展既有话题 API，附件归属、权限、并发和取消按 [话题领域契约](../../WORKSPACE_GROUP_TOPIC_DESIGN.md) 验证 |
| 全文搜索／跨设备草稿 | 各自需要接口、权限、数据和失败语义，单独评审；未完成时不能让 UI 承诺已经支持 |

P2P 离开提示中的“取消”不能先断开连接；确实结束后再进入保存结果页。
浏览器刷新／关闭的限制必须真实告知，不能把 `beforeunload` 当成可靠保存机制。
Workspace 隐藏消息偏好不得转化为删除、降低保留或改变其他成员可见性。

## 5. 全量切换与旧语言清理

新版本发布时，所有可达页面与浮层只使用新设计系统。默认、浅深色、角色或屏幕尺寸都不能回退旧 UI。
主题变体是同一语言的参数变化，不是旧样式兼容层。

验收前逐项清理：

- 全局旧 Token、被替换的 CSS、散落的颜色／圆角以及重复选择器。
- 与新组件重复的按钮、输入、编辑器外壳、消息动作、设置布局和反馈实现。
- 仍指向旧页面／抽屉／菜单的入口、不可达组件、旧快照和失效的视觉断言。
- 临时只用于开发的页面切换与新旧样式开关，不作为用户设置发布。
- 过时的视觉规范正文和链接，保留有用的历史记录但明确历史身份。

清理不能删除仍有领域职责的加密、幂等、上传校验、通知或权限代码。
最终检查全部主题与角色的可达页面，不只检查默认聊天截图。

## 6. 验证、发布与回退

执行命令与环境以 [Testing and release](../../development/TESTING_AND_RELEASE.md) 为准。
当前后端为 Go-only；Workspace 浏览器测试使用显式授权的本机一次性 PostgreSQL 数据，不能启动退役 Node API 或使用生产数据。

本版至少需要组件与重点回归、`pnpm lint`、`pnpm test`、`pnpm build`、Go P2P 和 Go Workspace 浏览器链路；涉及服务／SQL 时加相应 Go 与 PostgreSQL 门槛。
首次应用重写还需真人检查软键盘、安全区、阅读／返回和辅助技术，原型模拟视口不能替代。

发布候选必须具有全页面覆盖证明、版本／用户说明、兼容和风险记录。
通过 PR 评审，由 `timestarry` 决定合并；生产部署仍按现有独立授权与受控脚本执行。
发布失败的回退是恢复经过验证的整个兼容版本／镜像和既定数据权威，不能在新版本里保留一套旧 CSS 作为长期运行回退。
仅有 UI 改动不应要求数据库回滚；如新增领域迁移，需另行记录应用／schema 兼容范围。
