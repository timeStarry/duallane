## 结论

当前分支是供后续开发继续接手的 **v0.15.0 集成检查点**，不是可合并到 `main` 或部署到生产的发布候选版本。

本检查点如实保留 Echo、群聊话题、互动卡片和自定义 Agent Bot 的现有实现。服务端核心模型和大部分界面已经落地，但 Echo 的聊天命令及引导工作流尚未接入前端消息发送流程，浏览器级验收和发布验证也没有完成。生产部署与生产冒烟验证明确不属于本检查点。

## 未完成工作

### P0：连接 Echo 聊天命令与引导工作流

服务端已经提供以下接口，但 `apps/web/src/App.tsx` 的消息发送路径尚未调用它们：

```text
POST /api/workspace/interactions/commands
POST /api/workspace/workflows
GET  /api/workspace/workflows/:workflowId
POST /api/workspace/workflows/:workflowId/continue
POST /api/workspace/workflows/:workflowId/cancel
```

因此，当前在 Echo 对话中输入 `/need`、`/feedback`、`/publish`、`/help`、`/list` 等命令，仍会作为普通聊天文本发送。后续实现至少需要：

1. 在发送普通消息前识别 Echo Bot 对话中的已注册命令，并调用 `/api/workspace/interactions/commands`。
2. 保持未知命令、普通斜杠文本和非 Echo 会话的现有发送行为，不能误拦截用户文本。
3. 处理命令响应中的普通结果、互动卡片和 `workflow.start`。
4. 收到 `workflow.start` 后调用 `/api/workspace/workflows`，展示与工作流定义匹配的引导表单。
5. 接通工作流继续、完成、取消、过期及错误恢复状态。
6. 关闭、完成或取消引导流程后，将焦点恢复到原消息输入框或命令触发位置。
7. 明确命令与附件同时存在时的产品行为；当前发送路径没有命令专用阻断提示，也没有工作流失败后的独立草稿恢复状态。

仓库中没有可直接使用的 `WorkspaceEchoInteraction.tsx`。此前的未接线草稿已经移除，后续 Agent 不应假定该组件存在。

### P0：补完工作流并发和命令边界

- 当前没有强制“每位用户在同一个 Bot 会话中最多一个前台活动工作流”。需要明确唯一约束、并发启动结果和旧流程恢复策略。
- 工作流启动当前只验证操作者属于会话，没有完整复用命令路径的 Bot 会话上下文检查；`conversationId` 和 `botUserId` 的组合需要校验，不能启动一个未正确绑定目标 Bot 的流程。
- `/cancel` 当前解析可选工作流 ID；未提供 ID 时返回 `workflow_id_required`，不会自动定位当前用户在该 Bot 对话中的活动工作流。
- 命令和工作流的持久化限流仍需评审并补充覆盖，避免只依赖前端节流。
- 工作流继续、取消以及相关状态转换的 compare-and-swap 更新结果需要逐处复核；失去竞态时必须返回稳定冲突结果，不能报告虚假成功。
- 工作流 start/continue/cancel 当前没有完整传递请求元数据，也没有与命令执行一致的生命周期审计；需要补充不含内容的审计记录和稳定错误码。
- 应补充重复请求、相同 `clientInvocationId` 冲突、并发继续、过期后继续、取消与完成竞态的服务测试。

### P1：浏览器 E2E 与视觉验收

Topic、Echo 和 Agent Bot 的浏览器级核心流程尚未形成完整 Playwright 覆盖。至少需要验证：

- 双用户话题创建、加入、独立未读、消息同步、取消同步、关闭和归档。
- Echo 提案提交、正式需求状态、重复提案驳回、投票、主人管理和交付状态。
- Echo 斜杠命令、引导工作流、键盘操作、Escape、焦点恢复和错误回退。
- Agent Bot 创建、策略配置、私聊/群聊触发、卡片动作、令牌失效和权限拒绝。
- WebSocket 重连、重复事件和卡片 revision 覆盖本地状态时的幂等表现。

当前 Topic 和 Bot 前端覆盖主要是纯函数或组件级 Vitest，Echo 需求管理界面没有对应的专用前端测试；这些测试缺口应与 E2E 一并补齐。

尚未完成以下目标视口和显示模式的截图验收：

- `1440x900`
- `1024x768`
- `390x844`
- `360x800`
- 浅色、深色和 `prefers-reduced-motion: reduce`

需要特别检查话题侧栏、空间主人需求列表、Bot 管理页、互动卡片、弹层焦点循环、窄屏溢出和 44px 触控目标。

## 不可破坏的项目边界

- P2P 私密通道的消息和文件明文不得进入服务端持久化或日志。
- `#k=` 邀请片段只能停留在浏览器端。
- Workspace 必须继续由 `WORKSPACE_ENABLED=true` 显式启用。
- Workspace 改动必须保留 RBAC、配额预拒绝、消息保留和审计规则。
- 不得削弱 Fastify 日志脱敏、Bot 鉴权、卡片动作权限或安全响应头。
