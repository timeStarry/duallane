## 激活与回退

1. 发布准备 PR 由 `timeStarry` 合并并确认最终 CI 后，以检出所有者执行 `git pull --ff-only`。
2. 确认生产检出为干净 `main`，HEAD 与最新 `origin/main` 完全一致。使用**发布准备合并后的最终 40 位 SHA**，不能继续使用 UI PR 的合并 SHA。
3. 使用 root 执行正式协调器，设置 `GIT_OPTIONAL_LOCKS=0`；必要的 Git trust 例外仅作用于该进程与准确生产目录。

```sh
deploy/production/deploy.sh --expected-commit <final-merged-40-hex-sha> \
  --release-profile go-full --go-upgrade \
  --previous-release-snapshot /home/timestarry/duallane/backups/production/duallane-20260910T102919Z-ef5187348f8b.recovery.go-compose.snapshot.json
```

协调器负责新逻辑备份、固定镜像与 SQL 兼容验证、只读候选健康、旧 owner 停写与 drain、
新 owner 激活及最后替换网关。成功后核对公开 Web／静态资源／健康／鉴权边界、四个 owner、
版本与提交号、重启策略、新私有恢复快照和备份校验。

失败只按已验证快照恢复整版 Go 镜像并保持同一数据归属；不自动恢复旧数据库、不反向迁移、
不恢复退休 Node 服务。不得以裸 `docker compose up`、删除现有卷或修改健康条件替代正式流程。

最终激活结果、镜像身份、安全产物名称和开放项记录在发布 PR 的上线记录；未取得这些证据前保持“尚未激活”。
