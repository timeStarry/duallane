# Workspace Group Topic Design

## 1. 文档定位

本文定义共享空间的群话题能力，包括话题创建语法、子会话模型、话题卡片、话题消息同步、入口层级、权限、API、事件、保留策略和前端验收。

话题是群聊下的可加入子会话，不是普通标签，也不是全局独立群聊。实现必须复用 Workspace 的结构化消息、成员权限、附件、实时事件、审计和保留基础。

所有话题卡片、话题列表、同步卡片及新入口的视觉实现，在开发和上线验收时必须使用 `design-taste-frontend` Skill 进行设计审计。该审计用于检查层级、密度、对齐、响应式、状态和视觉一致性，不允许以通用卡片堆叠代替信息架构设计。

## v0.15 Implementation Status

v0.15 已实现本文定义的 P0 和 P1 主流程，当前事实边界如下：

- 群聊普通消息创建入口会在服务端重新解析第一个非空字符处的 `#[标题](正文)`。仅 human、group、纯文本、非回复消息进入该转换；合法语法使用原 `clientMessageId` 幂等地创建话题、创建者成员关系、首条话题消息和群聊创建卡，不再持久化一条普通语法原文消息。解析失败、中部语法、普通链接和图片语法继续按普通消息处理。
- `topics`、`topic_members`、`topic_group_projections`、`messages.topic_id` 和独立已读游标已经通过版本化迁移落地。服务端同时校验有效空间成员、所属群成员、话题成员、human 身份、状态和管理角色；被移出所属群后不能继续发现完整内容、加入、读取、发送或同步。
- 话题支持创建、发现、加入、退出、独立消息流、回复、未读、通知级别、关闭和归档。创建者自动加入；普通有效成员可创建和加入开放话题；`auditor` 不能创建、加入、退出或管理；owner/admin 可关闭或归档，创建者可关闭自己创建的话题。
- 话题消息默认仅存在于话题流。发送时可在同一事务中创建唯一的群聊引用投影；显式同步、取消同步、保留清理、话题关闭和归档会刷新或失效对应的注册卡片，群聊卡片不拥有原话题正文。
- 已实现 `topic.created`、成员变更、通知设置、状态转换、话题消息创建、同步和取消同步事件。事件投影按成员关系过滤，不先广播受限正文再依赖客户端隐藏。
- 话题创建、成员变更、消息、同步、通知和状态操作均写审计元数据及稳定结果码；审计不记录话题正文。状态转换和同步使用 revision、唯一约束或 compare-and-swap 防止重复与竞态误报。
- 前端已提供全局“话题”入口、群聊侧栏“本群话题”、筛选列表、独立话题消息页、创建卡和同步卡操作，并覆盖桌面与移动端导航、未读和通知状态。文件入口保留在工具菜单和群聊文件区域。

P2 尚未实现，继续保留更丰富的话题搜索、置顶和管理策略、摘要与 Bot 能力、跨设备草稿及高级归档策略。本文其他带有“未来”字样的内容同样不是 v0.15 已交付承诺。

## 2. 产品目标

- 让群成员从群聊中发起聚焦讨论，减少主群消息干扰。
- 让话题拥有独立消息流、成员关系、未读和通知状态。
- 允许话题消息按需以引用形式同步到所属群聊。
- 提供群内发现和跨群个人汇总入口。
- 保持话题与普通 Markdown 链接、图片语法和普通群消息语义互不干扰。

## 3. 非目标

- 不将所有话题显示为全局普通会话。
- 不把回复链直接改造成话题。
- 不将话题消息默认复制到群聊。
- 不允许话题绕过所属群聊成员权限。
- 不用表情回复代替加入、订阅或投票。
- 首期不支持跨群话题和公开空间话题。

## 4. 信息架构

### 4.1 全局主导航

当前左侧主入口中的“文件”调整到左下角工具菜单，原位置改为“话题”。

全局“话题”显示当前用户参与或发起的全部话题，按最近活动排序，并显示所属群聊、话题标题、未读数、状态和最近消息摘要。

文件库仍必须可发现：左下角工具菜单显示明确的“文件”图标和标签，群聊侧栏继续保留“本群文件”。不能只用不带文字的隐藏菜单降低文件功能可达性。

### 4.2 群聊侧栏

群聊侧栏已在“常驻消息”下提供“本群话题”。当前顺序：

```text
概览
常驻消息
本群话题
成员
文件
设置
```

本群话题支持“全部、我参与的、我发起的、未读、已关闭”筛选。

### 4.3 群聊消息卡片

创建话题后在所属群聊中显示话题卡片。卡片提供加入或打开话题入口，并显示创建者、标题、描述、正文摘要、参与人数、未读和状态。

### 4.4 移动端

全局话题和单个话题使用独立页面，不在聊天列上叠加窄抽屉。群聊侧栏中的话题列表使用子页面或 Sheet，但进入具体话题后应切换到完整消息界面。

## 5. 话题创建语法

### 5.1 规范格式

仅识别以下形式：

```text
#[话题标题](话题正文)
```

示例：

```text
#[设置页优化](希望将个人设置拆分为资料、隐私、聊天和通知四个分组。)
```

正文允许多行：

```text
#[设置页优化](
希望将个人设置拆分为四个分组。

目前页面存在层级扁平的问题。
)
```

### 5.2 解析规则

- 必须出现在消息第一个非空字符处。
- `#[`、`](` 和最终闭合 `)` 必须完整。
- 标题为 1 至 40 个 Unicode 字符，不能包含方括号或换行。
- 正文不能为空，长度遵循普通 Workspace 消息限制。
- 正文中的圆括号使用平衡解析，不用单条正则截断。
- 普通 Markdown 链接 `[文字](https://...)` 不触发话题。
- Markdown 图片 `![说明](https://...)` 不触发话题。
- 消息中部出现的 `#[标题](正文)` 按普通文本处理。
- 解析失败时整条消息按普通消息发送，不进行部分转换。
- 客户端可预览，但服务端必须重新解析和规范化。

### 5.3 执行边界

解析器只产生结构化创建意图，不直接写数据库。创建意图进入 `topic.create` 服务，执行 human 身份、有效空间与群成员、角色、幂等和审计校验；话题消息发送另有服务端频控。

客户端不能提交可信的创建者、Topic ID、所属群、成员、状态或同步关系。

## 6. 话题模型

话题绑定一个 `group` conversation，并拥有独立参与关系和消息流：

```text
群聊 conversation
└── topic
    ├── topic members
    └── messages with topic_id
```

实现没有把话题创建成普通 conversation，因此不会污染现有会话列表和成员管理语义。

v0.15 已落地以下领域表：

### topics

```text
id
space_id
conversation_id
title
description
created_by
status
allow_sync_to_group
created_at
updated_at
closed_at
archived_at
```

### topic_members

```text
topic_id
user_id
joined_at
left_at
last_read_message_id
last_read_seq
notification_level
```

### topic_group_projections

```text
id
topic_id
topic_message_id
group_conversation_id
group_message_id
projection_type
created_at
updated_at
removed_at
```

实现复用 `messages` 表并增加可空 `topic_id`：为空是普通会话消息，非空是话题消息。话题消息已经复用结构化内容、回复、保留和事件链路；更完整的编辑与撤回生命周期仍以后续实际接口为准。

## 7. 可见性与加入语义

当前语义是：群成员可发现话题摘要，加入后读取完整话题历史并发送消息。

- 创建者自动加入。
- 当前有效群成员可以加入开放话题。
- 未加入成员只看到创建者、标题、描述、状态、参与人数和允许公开的摘要。
- 话题成员可读取保留范围内的完整历史。
- 被移出所属群后立即失去话题访问权。
- 话题不能邀请所属群以外的成员。
- 群管理员可以关闭和归档话题，但不因管理身份自动绕过私密正文策略；若产品决定管理员可读，必须作为明确 Capability。

如果未来将“加入”改成仅订阅通知，必须升级产品和权限协议，不能只改按钮文案。

## 8. 状态与权限

状态：

```text
open -> closed
open -> archived
closed -> archived
```

- `open`：允许加入和发消息。
- `closed`：保留历史，只读。
- `archived`：从默认列表隐藏，可在归档筛选中查看。

服务端当前执行与以下 Capability 等价的权限边界：

```text
topic.create
topic.discover
topic.join
topic.read
topic.message.create
topic.sync_to_group
topic.manage
topic.archive
```

v0.15 使用上述固定角色与成员策略。后续群策略可以增加“禁止普通成员创建话题或同步消息”的配置；无论策略如何扩展，服务端权限始终是权威来源，前端按钮隐藏不能代替校验。

## 9. 话题创建卡片

群聊中的完整卡片结构：

```text
xxx 在本群发起了话题

#话题标题
低调色的话题描述
-------------------- 淡青色虚线
首条正文

[加入话题]
```

设计要求：

- 使用现有消息宽度，不铺满聊天列。
- 卡片圆角不超过现有 8px 组件规则。
- 标题使用消息正文层级，不使用页面级大标题。
- 描述使用辅助文字色，但必须满足可读对比度。
- 淡青色虚线只表达话题结构，不作为装饰性背景。
- 按钮状态稳定：`加入话题`、`打开话题`、`已关闭`、`无权访问`。
- 创建者、时间、参与人数和未读不与标题争夺视觉权重。
- 内容较长时使用受控摘要，不让卡片高度无限增长。
- 加载、失败、已删除、已归档状态必须有固定布局。

实现必须基于通用卡片注册体系，例如 `workspace.topic-created`，不在消息组件中硬编码一套特殊 DOM。

## 10. 话题消息与群聊同步

### 10.1 默认行为

话题消息默认只进入话题流，不出现在群聊，不增加普通群聊消息未读，也不改变普通群聊的最后消息摘要。

### 10.2 同步到群聊

话题编辑器已提供“同步到群聊”复选框，默认未选中。发送时：

1. 先事务性创建话题消息。
2. 创建成功后生成一条群聊引用投影。
3. 群聊投影不复制正文业务所有权，只引用原消息。
4. 打开投影时重新校验话题访问权限。

简略同步卡片：

```text
内容正文
-------------------- 淡青色虚线
#话题标题
```

同步卡片包含 `topicId`、`topicMessageId` 和 `projectionType=group_sync`。点击后打开原话题位置。

### 10.3 一致性

- 编辑原消息后更新同步投影摘要。
- 撤回或删除原消息后，同步卡片显示对应状态。
- 删除同步投影不能删除原话题消息。
- 同一话题消息最多一个群聊同步投影，由数据库唯一约束保证。
- 同步投影不能再次被解析为话题创建或同步来源。
- 附件不复制存储，访问仍按原附件和话题权限校验。

## 11. 消息协议

话题创建卡片和同步卡片使用通用卡片引用块：

```json
{
  "type": "card",
  "cardId": "card_xxx",
  "cardType": "workspace.topic-created",
  "schemaVersion": 1,
  "fallbackText": "#设置页优化"
}
```

话题消息仍使用 `duallane.message+json;v=1` 的文本、提及、链接、表情和附件块。未知卡片必须显示 `fallbackText`。

`#[]()` 只在群聊普通消息创建入口解析；话题内消息、同步卡片、Bot 消息和历史公开投影不重新解析。

## 12. Markdown 图片与链接兼容

三种语法必须按前缀和结构独立处理：

| 语法 | 结果 |
| --- | --- |
| `#[标题](正文)` | 仅群聊开头创建话题 |
| `![说明](https://example/image.png)` | 在普通 Markdown 文本块中渲染受控远程图片 |
| `[说明](https://example/page)` | 渲染普通外部链接 |

图片渲染要求：

- 仅允许 `http:` 和 `https:`。
- 使用懒加载和异步解码。
- 使用 `referrerPolicy="no-referrer"`，减少向外部图片源泄露页面地址。
- 图片有稳定最大宽度、高度、圆角和背景，不撑破消息列。
- `alt` 为空时使用低调的“图片”替代说明。
- 加载失败时显示替代文本，不显示破损图标。
- 图片不能注入 HTML、事件、样式或脚本。
- 普通 `[文字](url)` 继续使用现有新窗口、安全 rel 和 URL 白名单。

远程图片会向图片主机暴露用户 IP 和请求时间。产品应在隐私说明中明确这一点；后续可增加服务端图片代理，但代理必须具备 SSRF、防重定向、大小和 MIME 校验。

## 13. 已实现 API

```text
GET    /api/workspace/topics
GET    /api/workspace/conversations/{conversationId}/topics
POST   /api/workspace/conversations/{conversationId}/topics
GET    /api/workspace/topics/{topicId}
POST   /api/workspace/topics/{topicId}/join
POST   /api/workspace/topics/{topicId}/leave
GET    /api/workspace/topics/{topicId}/messages
POST   /api/workspace/topics/{topicId}/messages
POST   /api/workspace/topics/{topicId}/messages/{messageId}/sync
DELETE /api/workspace/topics/{topicId}/messages/{messageId}/sync
POST   /api/workspace/topics/{topicId}/close
POST   /api/workspace/topics/{topicId}/archive
```

所有读取和写入都重新校验适用的空间成员、所属群成员和话题参与关系。创建与消息发送执行幂等校验，状态转换执行 expected revision compare-and-swap，同步投影由唯一约束和状态条件保护。

此外，`POST /api/workspace/messages` 是 `#[]()` 的正式原子入口；独立 Topic 创建 API 和群聊语法入口最终调用同一 `topic.create` 领域服务。

v0.15 已发出以下事件：

```text
topic.created
topic.joined

topic.notification.updated
topic.closed
topic.archived
```

群成员收到话题摘要和群聊投影事件；话题成员收到完整话题消息事件。禁止先广播完整正文再由客户端隐藏。

## 15. 未读、通知与排序

- 全局话题列表按状态和最近活动时间展示，并提供参与、发起、未读、关闭与归档筛选。
- 群聊侧栏的话题列表显示当前用户的参与和未读状态。
- 未加入话题不产生话题消息未读。
- 同步到群聊的投影按普通群聊消息产生群聊未读。
- 邮件与 ntfy 通知读取话题自己的已读游标，不引用群聊游标。
- 话题通知级别支持全部、提及、免打扰。

## 16. 保留、附件与审计

- 话题消息保留应继承所属群默认策略，未来可由群策略收紧。
- 群聊消息清理不能留下指向不存在话题消息的可操作投影。
- 话题删除或归档不立即删除附件。
- 上传和下载继续使用 Workspace 额度，拒绝发生在传输前。
- 话题创建、管理、成员变更、同步和敏感拒绝写入审计元数据，不记录正文。

## 18. 验收标准

1. 只有群聊开头的合法 `#[标题](正文)` 创建话题。
2. 普通 `[]()` 链接和 `![]()` 图片不被解析为话题。
3. 解析失败时原消息完整保留，没有部分吞字。
4. 群外成员不能发现、加入、读取或同步话题。
5. 未加入成员只看到允许的话题摘要。
6. 话题消息默认不出现在群聊。
7. 勾选同步后群聊只出现引用投影，不复制正文所有权。
8. 取消同步和保留清理能正确失效同步投影；未来增加原消息编辑、撤回或删除接口时，必须同时更新同步投影。
9. 全局话题、群内话题和消息卡片三个入口权限一致。
10. 远程图片只允许 HTTP(S)，加载失败安全降级。
11. 普通链接保持现有安全跳转行为。
12. 未知话题卡片可通过 fallbackText 阅读。
13. 桌面、移动端、键盘和大字号布局无重叠或溢出。
