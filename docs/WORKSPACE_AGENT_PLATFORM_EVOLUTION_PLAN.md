状态：**方案已采纳，首版基础能力实施中，尚未验收／部署**。日期：2026-11-17。

本方案承接 [Bot 平台需求](WORKSPACE_AGENT_BOT_PLATFORM_REQUIREMENTS.md)与
[任务和产物契约](WORKSPACE_AGENT_RUNTIME_CONTRACT.md)，规划权限修正、业务能力和接入体验。
本文包含长期目标与首版范围；当前实例能力以能力发现和部署验收记录为准。
获采纳的部分应在实施 PR 中同步回所属产品、协议和 UI/UX 文档，本文保留决策与实施顺序。

首版实现与上线门槛见 [Agent 平台首版工作记录](backend/work-items/2026-11-17-agent-platform-v1.md)。
本次包括独立权限、可信任务、按需上下文、混合消息／文件、受控 Bot 来源和任务工具接入；

## 1. 产品目标与边界

让 Agent 成为共享空间中**能完成协作流程、身份明确、授权可解释**的成员。
“人类可以做的操作有对应 Agent 工具”是能力覆盖目标，不代表 Bot 自动继承创建者身份或全部权限。

优先满足两条任务：

1. **私有助手、按群开放**：只有创建者可私聊；创建者批准加入某群后，当前群友能看到并使用；
   群友不能因此私聊、搜索到其他私有信息，或将 Bot 带入其他群。
2. **完整协作操作**：在授权会话中找到指定消息／文件，读取、处理，回复到正确位置，按权限执行后续动作，
   并提供可核验的结果和失败状态。

本轮只面向 Workspace。P2P 的临时端到端加密与不持久化承诺不变。
不为对标飞书而新增日历、邮件、文档编辑等 DualLane 当前不存在的产品域。
不增加 Bot 模拟人类 Session 登录；用户委托身份若未来需要，应作为独立设计，不能复用 Bot Token 冒充用户。
模型、执行沙箱、模型账单与原生工具由外部 Agent Runtime 负责。

### 1.1 从鉴权聊天客户端推导平台能力

Agent 的模型负责理解与规划，SDK 是它使用 DualLane 的受控客户端。
评估单位不是“某类 Agent 能否完成一个例子”，而是一次可组合的操作：

```text
执行主体 + 可信请求／授权来源
  → 对可寻址对象执行操作
  → 在获准目的地读取、修改或交付内容
  → 获得可协调结果，并持续处理后续状态变化
```

由此需要一组共同对象：成员／Bot、空间／会话、话题／线程、消息、附件资源、事件、操作／任务。
对象都有类型、稳定标识、所属范围和生命周期；可变对象还需版本。
名字与 URL 不能代替对象身份，持有 ID 不能代替授权，传输 ACK 不能代替业务完成。
“可以读取来源”和“可以发送到目的地”也不能自动组合成“可以将来源披露到目的地”。

平台应覆盖 DualLane 已有产品域内适用于 Bot 的操作。每项操作分别规定身份、来源／目标约束、
状态、事件、失败与恢复语义，再一致投影至 JS／CLI／MCP 和桥接；不要求每种对象都有全部 CRUD。
人类专有或暂不支持的操作必须明确标注，不能借通用请求接口绕过身份边界。

### 1.2 基础能力复评：方法存在不等于可组合

以下是对当前代码和本提案前一版的复评，既包含已有基础，也包含尚缺的设计契约。

| 抽象能力 | 当前基础与缺口 | 本方案必须补齐的契约 |
| --- | --- | --- |
| 对象寻址与目的地 | SDK 发送以 conversation／reply ID 为主，人类消息域已有话题／线程；仅列“线程功能”不足 | 有类型的成员、消息、资源和目的地引用；引用回复与实际投递位置独立；作用域错误拒绝，不回退到父群 |
| 完整消息表达 | JS 可传结构化 content，MCP 发消息仅暴露 text，编辑主要为纯文本 | 同一规范消息结构支持文本、提及、多附件、链接与卡片；解析／构造／编辑保留语义，未知内容安全降级，不静默丢块 |
| 资源生命周期 | 已有上传预约、内容读取、状态查询和本地产物回收 | 区分服务器上的暂存、可用、已引用、失败、过期和撤销；规定上传未发出的协调、取消和回收；不把本地缓存清理当服务端回收 |
| 授权组合与内容流向 | 六项准入与任务授权已规划，来源读取与目的地发布仍需关联 | 授权明确绑定允许来源、处理边界和输出目的地；跨群、私聊到群、Bot 到 Bot 不隐式继承披露许可 |
| 状态观察与执行触发 | Gateway 当前事件准入主要覆盖创建／提及、指令和卡片动作；有限续传已有 | 编辑／撤回、资源失效、成员／授权变化用于同步和失效；是否唤醒模型另行决定；续传缺口需要受权再同步 |
| 操作结果与并发 | 发消息有幂等、卡片有 revision、上传可协调，但不是统一操作契约 | 状态查询、部分成功、结果未知、条件修改和取消语义覆盖各类副作用；区分已提交、已展示和人类已读 |
| 执行链与触发来源 | 已规划防递归，但描述因果字段本身不能防旁路 | 所有 Bot 写入由服务端关联可信任务／服务授权；后续触发核验直接发送者和起始授权，跨 API、重试及分支不能重置预算 |
| 能力发现与接入 | 已规划四维能力发现，实际文件与桥接限制分布多层 | 返回类型、尺寸／数量、速率、目的地和协议限制的有效交集；缺失授权有明确操作者申请路径，聊天文本不能自行批准增权 |

[Gateway 事件准入](../apps/backend/internal/workspace/botgateway/service.go)、

### 1.3 以覆盖清单控制完整性

实施时维护“产品对象 × 操作”的能力清单，每项记录：
适用身份、Scope 与对象／内容流向授权、输入输出类型、状态与事件、幂等／版本／失败恢复、
限制、服务端／JS／CLI／MCP／桥接覆盖、验收证据和交付阶段。

### 2.1 实际对话与接入记录中的痛点

本次证据来自当前需求讨论、Comet 接入与真实任务排查记录，以及上述代码核对；
不是全部用户历史的统计调查。文档仅归纳现象，不复制私聊正文、生产附件、凭据或任务标识。

| 观察与证据范围 | 升级要求 | 对应交付 |
| --- | --- | --- |
| 当前需求要求“仅创建者私聊、指定群内共享”，现有组合与投递规则无法一致表达 | 群内使用不推导私聊许可，所有入口共用决策 | P0 六项权限与核心预设 |
| Comet 的一次真实任务中，模型已生成约 3.58 MB PNG，但 SDK 大 Base64 校验栈溢出，尚未上传／发送就失败 | 区分生成、产物接收、上传、发送；提供可定位且不泄密的错误；保留可协调回执 | 线性编解码候选修复 PR #26；本方案的阶段反馈与大文件验收 |
| Comet 桥接仍导入旧运行包的解析器，只替换主运行包不能保证整个链路升级 | 检测运行包、独立桥接和解析依赖的兼容版本；保留操作者策略，避免重复消费者 | 接入版本协商、doctor 与升级验收 |
| 真实生图回复曾表示无法确认是否匹配参考图；这不能单独证明图片读取故障，但暴露了用户无法确认模型是否拿到参考材料 | 明确输入引用、附件授权和实际多模态适配；验收必须包含模型真实读取与结果交付 | 能力发现、桥接输入契约、参考图端到端验收 |
| 当前历史接口与三种工具入口的代码审查表明，“收到最近上下文”仍不足以稳定完成查找旧文件等任务 | 精确读取、受限搜索与分页，工具结果回到当前任务 | P1 受限工具会话与代表任务 |

实施后继续按匿名错误类别和获授权验收记录补充证据，不为产品分析默认采集或复制聊天内容。

## 3. 权限拆分：六项独立决策

| 决策 | 回答的问题 | 目标语义 |
| --- | --- | --- |
| 目录发现 | 谁能在空间目录／搜索中找到 Bot？ | 仅创建者、指定成员、空间成员；发现不授予私聊 |
| 私聊准入 | 谁能创建私聊及继续触发私聊？ | 仅创建者、指定成员、空间成员；按当前策略检查 |
| 群聊准入 | 谁能申请邀请，哪些群被批准？ | 邀请资格、创建者同意、群管理权限、具体群授权分别核验 |
| 群内触发 | 被批准的群中，谁能怎样唤醒？ | 人类使用范围、Bot 来源范围分别设置；提及／回复／指令或显式开启全量消息 |
| 内容读取 | 可以读取哪些历史和附件？ | 触发正文、历史窗口、元数据、预览、全文分别授权 |
| 业务操作 | 可以对哪些对象做哪些动作？ | Bot 能力、Token Scope、请求授权和目标资源规则共同决定 |

不再用 `private` 一个值推导所有六项。群内的合法成员展示来自当前群成员关系；
不要求将 Bot 放到全空间目录，也不自动打开个人资料、私聊或其他群访问。
“当前群成员可用”预设面向人类使用者，不隐式批准群内所有 Bot 互相调用；系统 Bot 也不天然豁免。

### 3.1 首选预设：私有助手，指定群共享

设置页提供一个可直接选择的预设，展开后仍可看到独立规则；不是新增含混的“仅群聊”枚举。

| 动作 | 创建者 | 已批准群的当前群友 | 群外普通成员 |
| --- | --- | --- | --- |
| 发起／触发私聊 | 允许，Bot 必须处于可用状态 | 禁止 | 禁止 |
| 在该群成员列表、提及列表看到 Bot | 是 | 是 | 无群访问权则不可见 |
| 在该群提及／回复／调用已开放指令 | 是 | 是 | 禁止 |
| 在全局目录发现 Bot | 是 | 否，除非单独开放 | 否 |
| 邀请到其他群 | 仍须满足目标群管理规则 | 禁止 | 禁止 |
| 读取历史、附件 | 按该会话的单独授权 | 触发不等于授予 Agent 全量读取权 | 禁止 |
| 修改 Bot 配置／凭据 | 创建者按管理权限操作 | 禁止 | 禁止 |

创建者的私聊准入保底不覆盖停用、封禁、空间禁用、文件权限或上下文授权。
创建者只能管理自己 Bot 的同意，不能绕过目标群管理员的管理权。

### 3.2 拟议策略结构

以下仅用于说明字段职责，实际 Schema 在 P0 评审确定：

```json
{
  "policyVersion": 2,
  "discovery": { "audience": "owner_only" },
  "direct": { "audience": "owner_only" },
  "groups": {
    "inviterAudience": "owner_only",
    "ownerApprovalRequired": true,
    "humanParticipantAudience": "current_members",
    "triggerMode": "mention_reply_command"
  },
  "context": { "defaultMode": "trigger_only" }
}
```

具体群的状态独立保存为 `pending / active / suspended / revoked`，关联邀请人、Bot 创建者同意、
目标群管理员同意或有效预授权来源、群标识、策略版本和时间；不能用一个含混的 `approvedBy` 代替双边准入。
同一人兼任两种角色时分别校验并记录，不要求重复人工审批；邀请申请、Bot 同意与群管理同意是不同动作。
只有 `active`、Bot 当前仍在群、本次触发人当前仍有群内使用资格时才允许触发。
独立名单必须按用途存储，不能让“允许发现的成员”自动变成私聊或群使用名单。

### 3.3 UI 行为与权限解释

保持现有 Bot 管理章节，按“发现与私聊”“群聊使用”“内容与操作”呈现。
先给出一句实际效果摘要：**仅你可私聊；已批准的 2 个群内成员可使用；不向空间目录公开。**

- 群成员点头像：显示允许公开的 Bot 身份与群内使用方式；无私聊资格时不出现可用的“发起私聊”。
- 输入框提及建议、成员列表与消息作者展示遵循同一群访问规则。
- 配置变更前显示受影响对象和收紧／新增范围；不能通过一个不相关开关顺带授权。
- 普通调用者只看到必要的拒绝原因，不泄露其他私有群、成员名单和内部配置；创建者可查看完整维度诊断。
- “检测这个成员能做什么”使用与实际请求同一决策服务，标记结果时点；检测不保证后续请求仍获准。

## 4. 服务端决策与请求身份

所有入口调用相同的领域级权限决策；网页按钮、Bot 会话摘要和 SDK 发现结果都是它的投影。
路由仍负责验证输入和身份，不在各入口复制一份近似判断。

```text
人类／Agent 入口
  → 验证 Session 或绑定 Bot 的 Token
  → 解析真实触发人、会话与目标对象
  → 统一权限决策
  → 现有 Go 领域服务
  → 幂等结果与内容无关审计
```

不能信任 Agent 在参数中自行填写的 `actorUserId` 或“群管理员说了可以”。
群任务引发的所有敏感读取和写入，均应绑定服务端签发、可撤销、短期有效的任务授权上下文，至少包含：
Bot、空间、触发事件、真实请求人、会话、允许操作／目标范围、有效期和策略版本。
其凭据保留在 SDK 控制层，模型只收到可公开的能力描述和引用 ID。
搜索、历史和附件读取同样受约束；不能由 Agent 自行省略任务上下文，降级为使用 Bot 总权限调用。
无任务上下文的操作仅允许明确区分的操作者或独立服务授权路径。启用新群共享策略和新业务工具时，
必须关闭对应的旧无上下文绕过路径；旧运行时不具备这项能力时安全拒绝该模式，不静默回退。

默认有效操作范围为：

```text
Bot 被授予的能力 ∩ Token Scope ∩ 当前会话授权
∩ 服务端记录的请求人可执行范围 ∩ 目标资源规则
∩ 当前策略／保留状态 ∩ 配额和系统上限
```

这防止群友借拥有管理员创建者的 Bot 执行群管理或读取创建者私聊。
Bot 是行为主体、触发人是请求主体，审计同时记录二者；创建者身份不是隐式兜底权限。
请求人的范围表达“可以委托什么、针对哪些目标”；作者和对象归属仍以执行主体 Bot 检查。
例如可允许请求人委托 Bot 修改同一任务中自己的 Bot 回复，但不允许编辑其他作者或任意历史 Bot 消息。
后台定时／主动任务另需明确的服务授权，不能伪造一个人类触发人或复用过期群任务。
人类委托身份和高权限自主服务暂不在首批范围。

私聊限制必须覆盖：Bot 专用入口、通用建聊 API、成员能力投影、旧私聊继续发消息、事件投递、
缓存资料／头像查询及直接猜测 ID。收紧准入不删除原有会话内容；既有消息的阅读与保留仍按人类会话规则处理。
撤销授权、移出群、移除成员后，队列、重试、缓存附件与产物引用均在下一次敏感读取／写入前重验。
关键状态检查与写入使用领域服务的事务／版本约束，覆盖检查后权限改变的竞争情况。
撤权不能收回已合法交付的字节，也不能保证外部模型遗忘；承诺的是停止后续获权读取和副作用。

### 4.1 读取、处理与披露分别约束

任务授权还应绑定允许使用的来源范围、外部处理边界及结果目的地。
对原附件复用／转发，检查来源读取、来源导出规则与目的地发布；将附件重新上传不能消除来源约束。
同群输入、同群回复可以由原任务直接覆盖，不要求每次工具调用再人工批准。
跨群、私聊到群或发给另一个 Bot，则必须有对应的来源→目的地授权，不能用两个独立权限拼接。

模型调用之前就按目的地与信任范围隔离输入和模型会话。
不把私聊材料先放入群任务模型上下文，再依赖提示词让模型“不要泄露”；
平台也不承诺自动识别自由文本、图片或衍生产物的全部信息来源。
受信任桥接负责保留来源引用与保守流向约束，平台负责其可验证的对象访问与发布边界；
无法安全分离的任务应拒绝组合或要求操作者显式授权，不静默扩大输入范围。
外部 Runtime 已合法取得字节后，平台无法控制其任意本机／外部工具，也不能保证它不通过其他渠道披露。
信息流验收限于平台受控对象操作和获验证桥接路径，不能据此宣称对任意接入 Agent 提供全局防泄露保证。

缺少授权时返回安全的缺失项及操作者控制面的申请入口；新增许可明确对象、操作、目的地与期限。
确认必须由有授权资格的人通过可信控制面完成；群聊中的“同意”、卡片自带参数或模型推断都不能自行授予权限。

## 5. 能力矩阵：按通用协作能力补齐

下表的“未完整提供”表示没有统一、获授权的 Agent 工具链，不代表对应人类功能不存在。
图片编辑、联网找图、机器人讨论是能力组合的验收案例，不各自定义一套 SDK 功能或专用业务流程。

| 能力 | 当前 Agent 基线 | 目标与边界 | 阶段 |
| --- | --- | --- | --- |
| 列出可用会话／最近上下文 | 已有；上下文有条数、时间、字符等限制 | 返回当前可执行能力；上下文不冒充历史分页 | P1 |
| 按 ID 精确读取消息 | 当前依赖触发投影或有限上下文 | 专用受权读取，不扫描历史猜消息；撤回／删除安全失败 | P1 |
| 历史分页与搜索 | 未完整提供；事件续传不是历史 | 会话内游标分页、作者／时间／关键词过滤；搜索范围必须与内容授权相交 | P1 |
| 成员解析与结构化提及 | 消息可携带结构化内容，缺少完整解析工具 | 在当前授权会话解析人类及 Bot；稳定 ID 发送／接收提及，同名返回候选，不猜身份 | P1 |
| 群聊触发与防递归 | 现有 Gateway 排除 Bot 消息触发 Bot | 统一配置来源身份、提及／回复／指令触发；开放 Bot 来源前必须具备可信因果链、去重、共享预算和停止控制 | P1 |
| 发送、普通引用回复、编辑自身消息 | 已有 | 统一调用契约、回执和幂等；不能修改其他作者消息 | P1 |
| 图片／文件接收与读取 | 已有受限附件接口和桥接输入，三入口暴露不齐 | 元数据、预览、原始内容和稳定引用统一授权；图片是文件能力中的类型化展示，不按用途另造通道 | P1 |
| 图片／文件发送与状态协调 | 已有上传、产物和受控媒体获取路径，入口暴露不齐 | 本地可信桥接产物、字节和显式启用的公共 HTTPS 来源统一校验；上传／消息两阶段回执、未知结果协调、批次逐项状态 | P1 |
| 卡片发送／更新／动作 | 服务端及 JS 已有部分路径，三种入口不齐 | revision 冲突、归属与动作授权；不执行任意卡片代码 | P1 |
| 线程、话题 | 普通 reply 不等于专用线程／话题能力 | 列出、读取、回复、参与／创建分别授权；不得误投父群 | P2 |
| 表情回应、置顶、转发、撤回 | 人类路径存在，Bot 工具链未补齐 | 逐项复用领域服务；置顶看群权限，转发同时检查来源与目的地，撤回遵守作者规则 | P2 |
| 会话及成员查询 | 现有列表不足以完成全部协作任务 | 可见资料、群内成员、Bot 当前群授权；最小信息投影 | P2 |
| 建群、成员增删、群设置 | 有人类路径，不能直接给 Bot Token 复用 | 先只读；写操作需任务授权、管理权限、预览和明确确认 | P3 |
| Bot 配置、凭据、空间治理、发布 | 存在部分独立管理／发布入口 | 归操作者控制面，日常群工具不默认暴露；单独审计与授权 | 后续独立评审 |

P1 的代表任务：**找到本群指定成员上周发的文件 → 读取获授权内容 → 处理 → 引用原消息发送结果。**
P2 再增加“回复到原线程”“按权限置顶”等步骤，不让首批依赖所有管理功能。
精确查历史、搜索与附件读取均要有明确新授权；原先“最近 50 条”授权不能升级成“搜索全空间”。

### 5.1 图片与文件的通用收发边界

SDK 提供受权读取、类型与大小校验、受控来源获取、上传、消息组装、进度／失败和交付回执。
同一套契约应覆盖图片、文档及平台允许的其他附件，不因内容来自搜索、生成或文件处理而改变权限规则。
模型侧使用受控引用／输入描述；本地文件收集仅由操作者信任的桥接执行，群消息不能指定任意本机路径。

- 输入：从触发消息或获权历史解析附件，按需读取元数据、预览或真实内容，保留来源和引用关系。
- 输出：接收真实产物或受控公共来源，上传后构造图片／文件附件消息，返回附件和消息回执。
- 图片编辑、OCR、搜索、格式转换、模型生成是外部 Agent／工具的业务能力；SDK 不据此声称自带这些能力。
- URL、链接预览卡片、附件是不同消息内容。发送 URL 不等于附件交付；卡片解析独立遵守站点白名单与抓取限制，
  可复用安全获取基础，但不能替代附件收发或借白名单扩大私有资源访问权。
- 平台能交付图片字节与 Runtime 能将其送入实际图像工具分别验收，不能用前者冒充后者。

### 5.2 通用提及、群聊触发与防递归

提及是消息原语，不是专门的“机器人讨论”功能：人类和 Bot 均使用稳定成员 ID，
SDK 能解析收到的结构化提及、查找当前群内可见对象并构造发送内容。
展示文字中的 `@名字` 不冒充结构化提及；提及本身不授予内容、调用、私聊或管理权限。

触发由服务端根据真实发送者身份、当前成员关系、群与 Bot 策略、提及／回复／指令方式统一决策。
正常群友使用与获准 Bot 来源复用该机制；不为“聊几轮”另建一套专用聊天协议。
现有 Bot 来源拒绝规则在安全机制完成前保留；升级后只能按显式来源策略开放，不能直接删除过滤条件。
每一跳同时核验直接发送者 Bot 的调用资格、起始委托的可传递范围和目标 Bot 的当前策略；
只有原始人类有权使用目标 Bot，不足以证明中间 Bot 有权代表该请求继续调用。

防递归是事件和任务系统的基础设施，由服务端强制执行，SDK／Runtime 配合停止与去重，不能只写进提示词：

- 服务端维护可信起始授权、根任务、父事件／任务、执行 Bot 与因果深度；后续 Bot 触发继承受限授权引用，
  不允许 Agent 自报请求人或伪造新根任务。定时／自主起始仍需第 4 节要求的独立服务授权。
- 所有 Bot 副作用入口都从可信授权上下文强制关联来源，在写入与事件产生的事务边界内传播；
  普通消息、卡片动作和以后新增入口均不能靠省略字段、换 API 或自行填写 task ID 创建新根。
- 每个目标 Bot 对同一事件去重；忽略自身回声。重复投递、断线续传、重试不得重复生成子任务或重置预算。
- 同一因果链共享总消息／触发／执行预算、最大深度和期限，原子扣减并跨重启保留；
  覆盖 A→B→A 及 A→多 Bot→多分支，不能只限制单个 Bot 的连续回复次数。
- 每次读取、工具执行和发送重新检查当前授权；A 不能把自身或创建者的全部权限传给 B。
  用户停止、撤权、超时或预算耗尽后，拒绝后续触发和副作用，并产生可解释的停止状态。

服务端强制计数其控制的触发、操作和执行许可；桥接约束实际模型调用与外部工具。
无法验证的外部 Token 消耗、费用或自主执行次数不展示为平台可强制的硬预算。

“讨论三轮”可由 Agent 在这套通用机制上安排轮次和总结，平台只强制执行获批上限与权限。
轮次是用户任务要求，系统预算是安全上限，两者不等同，也不把固定三轮写死为 SDK 能力。

### 5.3 状态观察不等于唤醒模型

区分事件可见范围、订阅范围与执行触发规则。只读状态事件仍须授权和最小投影，
但撤回、失效、移出群和权限收紧等控制信号不能被“只响应 @”规则挡住。
Runtime 可据此使缓存、引用与排队任务失效，无需调用模型，也不额外授权读取正文。
资源权限收紧后，仅可向原先已获该对象引用且连接身份仍有效的接收者发送最小失效标记，
不含私有正文、新对象、成员或敏感原因；Token／身份撤销应终止连接，不能借控制事件续权。
事件延迟或连接已关闭时，执行前的服务端重验仍是最终边界。

事件包含稳定标识、对象版本／序号和可用续传范围。出现游标缺口时标记状态不完整，
通过获权快照／差量恢复再继续依赖该状态；不得跳过缺口后将本地缓存当完整事实。
快照和事件衔接必须有明确版本／水位，避免再同步期间丢失变更。
消息编辑默认不自动创建第二次模型任务；撤回、删除或输入版本改变时，使未开始任务失效，
在途任务停止后续副作用或显式重新确认。若任务明确支持修改后继续，发布前必须校验新的输入版本。

### 5.4 按需上下文：授权范围、检索范围与模型输入分离

允许 Agent 在当前可信任务中按需拉取获权历史，而非每次固定塞入最近 N 条或全部历史。
当前 SDK 的有限 `getContext` 不等于完整历史工具；P1 的精确读取、分页与搜索共同完成此闭环。

| 范围 | 谁决定 | 不能混淆的边界 |
| --- | --- | --- |
| 可访问范围 | 服务端当前授权、会话历史可见性、保留状态及任务来源／目的地 | 入群、被提及或拿到消息 ID 不自动授予全部历史 |
| 本次检索结果 | 任务查询条件、分页、单次／累计返回量与查询预算 | 可以分批读取，不代表允许无限扫描、扩大时间范围或跨会话 |
| 实际模型输入 | SDK／获验证桥接按模型能力与任务预算组装 | 合法取得的内容不必全部送入模型，模型窗口大小也不扩大读取授权 |

建议采用以下通用流程，不规定所有任务使用相同条数：

1. 初始输入保留精确触发消息和必要身份／会话／时间，按授权包含直接引用、少量局部上下文、
   当前任务状态及可用检索能力；不默认携带整个群历史或全部附件字节。
2. Agent 先限定当前会话／线程、时间、作者或对象类型；根据任务需要选择精确读取、锚点附近消息、
   分页或搜索。结果优先提供可定位引用、必要片段与附件元数据；不得用无权片段、计数或结果排序泄漏内容。
3. 只展开相关原消息、回复链或附件内容；获得工具结果后仍按总输入预算组装。
   每次读取重验任务、请求人、Bot、资源和允许流向，游标／引用不是授权凭据。
4. 结果注明查询范围、排序、水位、是否还有下一页、片段／正文截断及可继续读取的位置。
   分清“当前范围无匹配”“未搜索／未读完”“工具不支持”“预算耗尽”和安全的访问失败；
   没有找到不能被表述为历史中一定不存在，不能为解释失败泄漏无权对象存在性。
5. 达到证据充分、检索预算或期限即停止；材料不足时说明覆盖限制或询问澄清，
   不允许无界翻页，也不靠补造历史内容完成任务。

分别设置服务端检索预算与桥接模型输入预算：前者包括单次／累计结果量、附件字节、调用数、速率与期限；
后者覆盖指令、历史、工具返回、图片／附件表示和输出预留，按实际模型适配估算并留余量。
上下文过大时优先缩小查询、分段展开、移出无关原文并保留引用，不静默丢失触发指令或伪装完整上下文。
平台强制受其控制的查询限制，不声称能控制任意外部 Runtime 自行追加的模型输入或费用。

区分短期任务状态、会话工作上下文与长期记忆。长任务可由 Runtime 保存有界工作摘要，
标明来源消息／版本、覆盖时间、未决事项及事实／推断；摘要不是原始证据，关键结论可回查原文。
摘要、索引、检索缓存与长期记忆受原始范围、撤回／保留和输出目的地约束；
无法验证其来源仍获权时，不继续作为当前获权上下文使用。跨任务长期记忆／后台长期摘要沿用显式启用原则，
不默认建立跨群用户画像或全空间记忆，也不承诺收回外部模型已收到的内容。
历史、摘要、网页和附件均作为带来源的不可信材料，不能因进入上下文而变成系统指令或授权材料。
语义检索可作为未来检索实现，不是完成首批精确读取、分页与过滤的前置依赖。

## 6. SDK、CLI、MCP 的统一操作契约

参考 lark-cli 的能力分层与 Schema 发现方式，而不是仅增加大量零散方法。
建立版本化操作目录作为 JS SDK、CLI、MCP、帮助与 Skill 示例的共同契约来源。
每项 Agent 操作有一份可审查的描述，包含：

- 稳定操作名、版本、输入／输出结构、分页语义与引用类型。
- 支持的身份、Scope、会话／资源条件、读写性质和风险类别。
- 幂等键、预期 revision、部分成功、取消和结果未知时的处理方式。
- 对象与目的地引用、消息块／资源类型、生命周期、状态事件、来源到目的地约束。
- 操作状态查询、重放／再同步要求、输入版本和有效限制，及不支持时可说明的降级行为。
- 示例、常见安全错误、最小成功回执及证据要求。

该描述驱动 SDK 类型／封装、CLI 参数、MCP 工具 Schema 和文档的一致性检查或生成。
服务端权限决策仍由 Go 代码执行，不能把工具描述或客户端参数当作授权。
采用仓库现有协议工具优先；若引入新的生成器，应先验证维护成本，不为方案先添加依赖。
同一个新操作要么对三入口同时提供契约与一致验证，要么明确标为该入口尚不支持。
拟议操作例如 `messages.search`、`messages.get`、`messages.reply`、`reactions.add`；
不能因一个“消息权限”就默认开放全部消息读写和管理动作。

静态 Schema 只说明系统支持的操作，不包含私有对象信息；动态 capabilities 则针对当前
可信请求人、Bot、任务、会话和目标对象给出安全投影，不能仅检查 Bot 的总权限。

拟议能力发现返回四种不同状态：

| 维度 | 含义 |
| --- | --- |
| 平台实现 | 该操作和协议版本是否存在 |
| 当前授权 | 当前 Bot／Token／会话／任务是否允许 |
| Runtime 能力 | 当前桥接是否声明并通过对应适配探测，如支持参考图输入 |
| 当前可执行性 | 目标是否仍有效、额度是否够、任务是否被取消等动态条件 |

返回结果应注明时点、策略版本和有效范围；声明“支持图片输入”不等于某个模型真的理解了图片。
按当前任务发现少量相关操作，避免把全部业务 Schema 和大段 Skill 一次塞给模型。

CLI 可分“业务任务快捷操作”和“结构化操作调用”；MCP 使用相同结果结构。
不增加能绕过 Bot 命名空间、调用人类 Session API 或任意 URL 的通用请求后门。
预览／dry-run 不能创建传输、调用模型、写审计业务成功或消费一次性授权；正式执行必须重新鉴权。

### 6.1 从模型调用到任务回执的闭环

P0 建立必须的可信任务授权边界，P1 在此基础上交付受当前任务约束的工具会话／调用通道，
可复用现有 MCP，具体传输在实施时确定，不另造第四套工具框架。
桥接中的模型只获得本任务必要的 Schema 和引用，不自行持有通用 Bot Token。
SDK 控制层携带服务端认可的任务上下文执行每次调用，将工具结果、操作幂等键和回执接回同一个耐久任务。
只有 JS／CLI／MCP 方法清单而模型桥接无法安全调用，不能算完成 Agent 能力交付。

### 6.2 一致的操作结果、冲突与取消

为有副作用的操作定义稳定关联标识和幂等语义，复用既有领域回执，补齐必要的受权状态查询。
统一区分未受理、已受理、已提交、明确失败、部分成功与结果未知；不把网络超时直接归为可重试失败。
查询未知结果不能触发第二次副作用；协调与重试重验当前授权，也不能暴露撤权后的对象内容。
消息编辑等可变操作采用版本／条件写入，流式或渐进更新复用同一机制，不能静默覆盖其他更新。

取消分为停止后续任务、终止可取消的在途工作、协调可能已提交的结果；
撤回已发送消息是独立的获权操作。取消确认不承诺回滚已经提交的副作用或收回已交付内容。
提交回执仅证明服务器接受结果，不证明对方客户端已展示或人类已读；后两种证据仅在产品明确提供时声明。

## 7. 通用 Skill 与接入契约

把平台接入、业务使用、运行维护分开，避免模型把安装脚本、群消息和授权当成同一种指令。

| 模块 | 内容与受众 | 不承担的职责 |
| --- | --- | --- |
| 接入指南 | 安装核验、一次性配置、复用已有凭据、能力协商，面向操作者和接入 Agent | 不替用户批准 Scope，不在群内执行安装指令 |
| 消息协作 Skill | 发现会话、精确读取、搜索、回复、线程、提及、回应 | 不直接读取本机文件或使用创建者 Session |
| 文件与产物 Skill | 输入格式、授权读取、实际 bytes、产物引用、上传及回执 | 不把 URL／模型成功文案当作已交付 |
| 维护指南 | 单消费者、doctor、升级、排空、恢复与回滚，面向操作者 | 不默认成为普通群用户可调用工具 |

上表是发布内容的职责划分，不强制每个平台都安装四个独立 Skill。
支持 Skill 的宿主按官方方式安装并确认已加载；不支持的宿主读取版本化接入文档和结构化 Schema。
两者必须满足同一工具协议，不能将“安装过一个目录”当作能力已就绪的证据。

建议接入流程：

1. 只读发现已有 profile、单消费者和受信任服务入口；不输出凭据，也不默认重新配对。
2. 核验 App／SDK／Skill／桥接协议版本、摘要和可用能力；版本不兼容给具体缺失项。
3. 没有凭据时才发起浏览器一次性配置，由人类确认身份、Scope 和会话范围。
4. 操作者显式选择通用命令桥接；桥接声明可用输入／产物格式和自己的实际执行隔离能力。
5. 在隔离合成环境完成格式与失败探测；用授权测试会话完成真实收发和模型能力验收。
6. 选择已验证运行包，确保只存在一个消费者，再将服务标为 ready；队列为空不等于健康已证明。

官方包、独立桥接、策略、supervisor、凭据分别管理。升级必须同时发现旧解析器依赖，不能只换主进程。
静态 Skill 不是授权材料，不含真实 Token、内部路径或用户内容；不能覆盖更高层的群聊保密／只读政策。

## 8. Runtime、工具调用和产物的职责

保留既有耐久任务和产物基础，不为业务工具另建一套互不相认的任务系统。

- Gateway 决定投递、当前授权与触发投影；SDK 持久接收后 ACK。
- 任务保存服务端认可的请求身份及授权引用，按会话串行；模型调用不承诺严格仅一次。
- 每次敏感工具调用均重验授权；任务开始时通过不代表结束前仍有权限。
- Runtime 保留可恢复阶段与幂等回执，桥接负责模型调用、实际工具适配和原生产物采集。
- 模型会话与记忆按 Bot、会话和信任范围隔离；不得把创建者私聊的模型线程或记忆直接复用于群任务。
- 模型输出属于不可信输入。平台不靠提示词保证保密，也不声称能自动识别所有图片／文档中的秘密；
  由输入隔离、可执行工具边界、受信任桥接策略和输出目的地检查共同限制影响。
- 产物需要真实字节、类型／大小／摘要校验和对应消息回执；自然语言“已发送”没有交付效力。
- 同群复用还需当前来源消息和附件授权；跨会话导出不是默认能力，转发必须检查两端权限和显式目的地。
- 未知上传结果先查询协调；部分成功保留回执。升级和修复都不自动重跑旧失败任务或补发。

### 8.1 资源引用、生命周期与链路限制

附件资源独立于消息存在，消息引用资源而不是持有任意存储 URL。
定义预约／暂存到可用、被消息引用、失败、过期或撤销的合法转换；状态是语义要求，
不预先强制每种状态对应一张表或一个新字段。明确上传取消／超时、已上传未发送、
消息发布失败、引用删除后的保留与回收责任，服从既有配额、审计和保留规则。
状态协调复用原上传／发布身份；跨会话复用必须重新检查来源与目的地，不能只复用裸附件 ID。

模型侧使用有界资源描述和获权引用；真实字节由可信桥接按需传给实际工具。
不要求大文件整段 Base64 进入语言模型上下文，也不把任意本地文件路径开放成群工具。
文件类型、输入输出尺寸、数量与累计大小、时间及并发限制取平台、授权、SDK、桥接和工具的有效交集，
在执行前可发现；超限明示失败或获准降级，不静默截断、压缩或用预览冒充原文件。

## 9. 数据模型与迁移

建议使用版本化策略与独立列表／群授权记录，避免继续修改 `visibilityPolicy` 的含义。
具体 SQL、索引和表名由 P0 实施设计确定，迁移路径必须先评审。

1. 只读盘点旧值、名单、活跃／待审批群、现有私聊、Scope、context grants 与规范化行为；报告只含必要标识与数量。
2. 新字段／表采用增量迁移，默认不授予新能力；历史授权保留来源与版本。
3. `private` 可明确迁移为创建者私聊，但不能仅凭 `allowGroup=true` 推断全部旧群友已获使用权。
4. 对原本受可见性名单限制的群，先保留原触发人集合；不能自动改为全体群成员。
5. 旧 `groups` 已被规范化且缺少来源时标记待确认，不猜原意、不自动开放全空间或成员私聊。
6. 创建者看到可理解的迁移预览，明确确认后启用“私有助手、指定群共享”；每个群仍需满足群管理同意。
7. 将授权改写从普通读取／概览／启动规范化路径移出；一次性迁移幂等执行并产生内容无关审计。
   创建者私聊保底不等于同意读取历史；旧正规化补出的 `allow_context` 需核验显式同意来源，
   无法证明时按触发正文模式处理并提示创建者确认。
8. 旧客户端对 V2 策略只读或安全拒绝修改，不允许保存旧表单时覆盖／放宽新维度。

SDK 接入不保留旧运行包兼容通道：App1.2 对全部 Bot 要求兼容的稳定1.x SDK，
最低1.2.0。HTTP、配对与 WebSocket 握手统一校验版本声明；缺失、非法、过旧或不兼容时
返回426 `sdk.upgrade_required` 和官方升级入口，运行时停止重试后升级。
保留历史策略和凭证仅用于避免改授权、重复配对，不代表允许旧 SDK 继续运行。
版本声明不构成鉴权；升级不得跳过 scope、任务、对象和会话授权。

发布采用受控策略版本切换，同一在线 Go 所有者执行决策；不能开启两个生产写入者。
回滚不仅是换旧镜像：若旧版本不能解释 V2 策略，应先暂停相关 Bot 操作并恢复兼容的保守策略，
保留 V2 记录和审计，防止旧二进制将新策略读成开放默认值。回滚演练是启用 V2 的前置门禁。

## 10. 可观测性与错误反馈

统一关联 `eventId / taskId / operationId / conversationId / messageId / attachmentId`，
操作者看到阶段、错误码、授权维度、重试建议与回执；普通聊天反馈不含内部身份、路径、凭据或模型 stderr。

需分别呈现：未投递、权限拒绝、已接收排队、执行中、生成失败、读取／上传失败、发送失败、
部分成功、结果未知、取消、完成。进程存活、Gateway 连接、桥接可执行、任务失败是不同健康维度。
拒绝原因从同一决策结果生成，UI／doctor／能力发现不能分别猜。
授权变化后能力缓存失效；缓存和旧任务快照不能作为持续权限证明。

## 11. 实施顺序与每阶段完成门槛

| 阶段 | 交付 | 完成门槛 |
| --- | --- | --- |
| P0：基础契约与权限 | 对象／操作覆盖清单、六项策略、来源到目的地与可信任务边界、统一决策、入口修复、迁移预览、UI 摘要 | 核心私聊／群共享全链通过；权限不能拼接为跨目的地披露，旧策略不扩权，撤权和回滚通过 |
| P1：客户端能力闭环 | 规范消息与引用、精确读取／搜索、资源收发和生命周期、状态同步／再同步、操作结果协调、能力发现、受限工具会话及防递归触发 | 消息混排及真实资源交付、失效／输入变更、断线缺口、未知结果协调、获准 Bot 触发与循环预算通过；三入口契约一致 |
| P2：协作操作 | 线程／话题、回应、置顶、撤回、跨目标转发等逐项工具 | 原线程回复和允许的置顶任务通过；跨对象越权拒绝，三种客户端行为一致 |
| P3：接入体验与受控管理 | 模块化 Skill、适配探测、迁移／升级诊断，评审后的群管理能力 | 多种外部 Runtime 复用通用协议，冷接入／升级／撤销／单消费者均可复现验收 |

能力描述和接入指南随 P0／P1 同步交付；P3 是完善与跨宿主验证，不是把必要文档延后。
每阶段可拆成小 PR：先契约与失败用例，再领域实现、三入口对齐、真实验收和正式发布。
P1 内先建立对象／消息／资源闭环，再补状态与失败恢复，最后在可信写入来源和预算具备后开放 Bot 来源触发。
覆盖清单区分首批基础引用与 P2 话题／线程等业务操作；不以有引用类型冒充整类业务已交付。
P0 是功能扩展的前置条件；不能一边留下权限旁路，一边批量开放写工具。
不为本方案预先承诺具体发布日期或全部功能同一大版本上线。

## 12. 验收矩阵

| 场景 | 必须观察的结果 |
| --- | --- |
| 创建者私聊／群友尝试私聊 | 创建者可用；群友从头像、目录、旧会话、Bot 专用及通用 API 均不能绕过准入 |
| 创建者批准入群 | 当前群友可在成员／提及列表见到并按规则触发；群外不可见不可触发 |
| 群友邀请到另一群 | 未授邀请资格时拒绝；即使具备邀请资格仍检查目标群和 Bot 双方同意 |
| 指定成员／全体群员规则切换 | 预览准确，保存后摘要、按钮、投递与操作权限一致；不改变私聊范围 |
| 移除群员、移出 Bot、撤销群／上下文／Token | 新触发和敏感工具调用及时拒绝；队列、重试、文件及缓存产物不绕过 |
| 群友要求读取创建者私聊或代行管理 | 请求人限制生效；不泄露对象存在性、历史正文、凭据或管理资料 |
| 独立读取权与发送权组合 | 平台受控操作与获验证桥接路径中，无来源→目的地授权则拒绝跨范围读取／交付；模型输入先隔离；不声称能识别任意外部输出的全部来源 |
| 对象寻址与规范消息 | 同名消歧；引用与投递位置独立；文本＋提及＋多附件等结构读写／编辑不静默丢失，未知类型安全降级 |
| 历史文件查找 | 搜索只覆盖获权范围；支持游标、同名消歧、撤回／删除与限窗；无权结果不进入总数或片段 |
| 按需上下文与覆盖信息 | 短指令不灌入整群历史，历史任务可逐步定位与展开；返回范围／分页／截断信息，预算耗尽不冒充无结果，不能借摘要或游标越权 |
| 图片／文件通用收发 | 不同获权来源经同一收发契约交付真实附件；来源限制、格式、大小、配额、部分失败和回执一致；URL／卡片不能冒充附件 |
| 真实参考图／生成图／文档 | 模型实际可读，收集真实产物，IM 回执回读正确；声明和真实能力分别验收 |
| 群内结构化提及与来源策略 | 人类及 Bot 身份解析、接收／发送提及正确；获准来源触发，未获准来源不触发；提及不增加私聊或内容权限 |
| Bot 互相提及、循环与分支 | 正常协作可完成；自身回声、重复事件、A→B→A、多分支、重启与重试不能绕过共享预算；停止和撤权后拒绝后续副作用 |
| 状态同步、输入版本与续传缺口 | 撤回／授权变化使缓存和未来操作失效，不默认调用模型；编辑不重复触发，旧结果不冒充最新输入；快照／事件衔接无丢变更 |
| 资源生命周期与有效限制 | 上传未发、发布失败、取消、过期和回收均可协调；实际工具限制执行前可见，不能以平台上限冒充整链路支持 |
| 通用操作与取消 | 提交前后断线均可区分明确失败和未知结果；冲突不静默覆盖，查询不重复副作用；取消不虚称撤销已提交结果或人类已读 |
| 大文件与畸形编码 | 固定边界、规范 Base64、累计限制、线性处理和内容无关错误；不依赖压缩用户图片规避 |
| 多附件部分成功、丢回执、断线／崩溃／取消 | 已确认步骤不重复，未知结果先协调，有限重试，不把 ACK 当完成 |
| JS／CLI／MCP 同一操作 | 目标、授权、分页、错误、幂等、revision 和回执语义一致 |
| Skill 接入与更新 | 明确实际可用能力；旧 parser 依赖可发现；不重配对、不覆盖独立策略、不启动双消费者 |
| 移动与桌面 | 390×844／320px 和桌面，私聊禁用入口、新权限摘要与拒绝解释一致且键盘可用 |
| 旧数据升级／旧客户端／回滚 | 无隐式扩权、无读路径改授权；旧版本安全拒绝不支持的策略 |

证据分四层记录：纯协议／单元测试；真实 Go＋隔离 PostgreSQL；真实发布资产的合成事件 UI；
获授权真实 Agent＋真实 IM。任一层通过都不能替代其余层。
实施 PR 运行[测试与发布矩阵](development/TESTING_AND_RELEASE.md)要求的适用门禁，
数据库和失败／并发回归必须使用一次性数据；真实测试不得未经授权向群发送消息或重试用户任务。

## 13. 采纳建议与评审重点

建议先采纳本方案的产品方向、六项权限边界、P0 优先级和分阶段验收方法。
策略结构、Scope 命名与任务授权上下文格式在各阶段实施设计中细化，避免将示意字段误当已发布 API。

评审重点是：旧群策略的保守迁移如何让用户理解；目录发现与群内资料投影如何一致；
新增业务操作如何绑定真实请求人；不同 Runtime 如何声明并证明真实输入／工具／产物能力。
在这些条件明确前，维持 Bot 独立身份，不引入“以创建者身份执行所有操作”的捷径。
